# 第一章 绪论

## 1.1 数据结构的基本概念

### 1.1.1 基本概念和术语

**数据**

数据是信息的载体，是描述客观事物属性的数、字符以及所有能输入到计算机中并被计算机程序识别和处理的符号的集合。

**数据元素**

数据元素是数据的基本单位，通常作为一个整体进行考虑和处理。一个数据元素可由若干个**数据项**组成，数据项是构成数据元素的不可分割的最小单位。

例如：学生记录就是一个数据元素，它由学号、姓名、性别等数据项组成。

**数据对象**

数据对象是具有相同性质的数据元素的集合，是数据的一个子集。

例如：整数数据对象是集合 N = {0, ±1, ±2, …}；字母字符数据对象是集合 C = {'A', 'B', …, 'Z'}。

**数据类型**

数据类型是一个值的集合和定义在此集合上的一组操作的总称。

1）原子类型：其值不可再分的数据类型。如 `bool` 和 `int` 类型。

2）结构类型：其值可以再分解成若干成分（分量）的数据类型。例如，数组的值由若干分量组成的数据类型。

**抽象数据类型（Abstract Data Type, ADT）**

抽象数据类型是指一个数学模型以及定义在该模型上的一组操作。ADT 的定义仅取决于它的一组逻辑特性，而与其在计算机内部如何表示和实现无关。
    ADT 抽象数据类型名 {
        数据对象：<数据对象的定义>
        数据关系：<数据关系的定义>
        基本操作：<基本操作的定义>
    } ADT 抽象数据类型名

其中，基本操作的定义格式为：
    基本操作名(参数表)
        初始条件：<初始条件描述>
        操作结果：<操作结果描述>

赋值参数只为操作提供输入值；引用参数以 & 打头，除可提供输入值外，还将返回操作结果。

### 1.1.2 数据结构的三个要素

**数据的逻辑结构**

逻辑结构是指数据元素之间的逻辑关系，它与数据的存储无关，独立于计算机。分为：

1）**线性结构**：有且仅有一个开始元素和一个终端元素，并且所有元素最多只有一个直接前驱和一个直接后继。典型例子：线性表、栈、队列、字符串、数组、广义表。

2）**非线性结构**：一个元素可能有多个直接前驱或直接后继。典型例子：树、图、集合。

| 结构类型 | 元素关系 | 典型代表     |
| ---- | ---- | -------- |
| 线性结构 | 一对一  | 线性表、栈、队列 |
| 树形结构 | 一对多  | 树        |
| 图状结构 | 多对多  | 图        |
| 集合结构 | 无关   | 集合       |

**数据的存储结构（物理结构）**

存储结构是指数据结构在计算机中的表示（又称映像），包括数据元素的表示和关系的表示。存储结构是逻辑结构用计算机语言的实现，依赖于计算机语言。

1）**顺序存储**：把逻辑上相邻的元素存储在物理位置上也相邻的存储单元中，元素之间的关系由存储单元的邻接关系来体现。

优点：可以实现随机存取，每个元素占用最少的存储空间。缺点：只能使用相邻的一整块存储单元，可能产生较多的外部碎片。

2）**链式存储**：不要求逻辑上相邻的元素在物理位置上也相邻，借助指示元素存储地址的指针来表示元素之间的逻辑关系。

优点：不会出现碎片现象，充分利用所有存储单元。缺点：每个元素因存储指针而占用额外的存储空间，且只能实现顺序存取。

3）**索引存储**：在存储元素信息的同时，还建立附加的索引表。索引表中的每项称为索引项，一般形式是：（关键字，地址）。

优点：检索速度快。缺点：附加的索引表额外占用存储空间。另外，在增加和删除数据时要修改索引表，因而会花费较多时间。

4）**散列存储**：根据元素的关键字直接计算出该元素的存储地址，又称哈希（Hash）存储。

优点：检索、增加和删除结点的操作都很快。缺点：如果散列函数不好可能出现元素存储单元的冲突，而解决冲突会增加时间和空间开销。

**数据的运算**

施加在数据上的运算包括运算的定义和实现。运算的定义是针对逻辑结构的，指出运算的功能；运算的实现是针对存储结构的，指出运算的具体操作步骤。

常见运算：

* 创建和销毁
* 插入和删除
* 查找
* 修改
* 排序
* 遍历

## 1.2 算法的基本概念

### 1.2.1 算法的定义与特性

**算法**是对特定问题求解步骤的一种描述，它是指令的有限序列。其中的每条指令表示一个或多个操作。

算法具有五个重要特性：

1）**有穷性**：一个算法必须在执行有穷步之后结束，且每一步都在有穷时间内完成。

2）**确定性**：算法中每条指令必须有确切的含义，读者理解时不会产生二义性。在任何条件下，算法只有唯一的一条执行路径，即对于相同的输入只能得出相同的输出。

3）**可行性**：算法中描述的操作都可以通过已经实现的基本运算执行有限次来实现。

4）**输入**：一个算法有零个或多个输入，这些输入取自某个特定的对象的集合。

5）**输出**：一个算法有一个或多个输出，这些输出是与输入有着某种特定关系的量。

### 1.2.2 算法的目标

一个好的算法应该达到以下目标：

1）**正确性**：算法应能够正确地解决问题。正确性包含四个层次：

* 程序不含语法错误
* 对于几组输入数据能够得到满足规格说明要求的结果
* 对于精心选择的典型、苛刻而带有刁难性的几组输入数据能得到满足规格说明要求的结果
* 对于一切合法的输入数据都能产生满足规格说明要求的结果

2）**健壮性**：当输入非法数据时，算法能适当地做出反应或进行处理，而不会产生莫名其妙的结果。处理错误的方法可以是返回一个表示错误或错误性质的值。

3）**可读性**：算法主要是为了人的阅读与交流，其次才是机器执行。可读性好有助于人们理解算法。

4）**效率与低存储量需求**：效率指的是算法执行的时间；存储量需求指算法执行过程中所需要的最大存储空间，这两者都与问题的规模有关。

## 1.3 算法复杂度分析

### 1.3.1 时间复杂度

语句频度是指一条语句在算法中被重复执行的次数。算法中所有语句的频度之和记为 T(n)，它是该算法问题规模 n 的函数。时间复杂度主要分析 T(n) 的数量级。

算法中基本运算（最深层循环内的语句）的频度与 T(n) 同数量级，因此通常采用算法中基本运算的频度 f(n) 来分析算法的时间复杂度。

时间复杂度记为：

$$T(n) = O(f(n))$$

式中，O 的含义是 T(n) 的数量级，其严格的数学定义是：若 T(n) 和 f(n) 是定义在正整数集上的两个函数，则存在正常数 C 和 n₀，使得当 n ≥ n₀ 时，都满足 0 ≤ T(n) ≤ C·f(n)。

**常见渐进时间复杂度排名如下：**

$$O(1) < O(\log_2 n) < O(n) < O(n\log_2 n) < O(n^2) < O(n^3) < O(2^n) < O(n!) < O(n^n)$$

**几种特殊的时间复杂度：**

1）**最好情况**：最少运行次数时的复杂度。

2）**最坏情况**：最多运行次数时的复杂度。

3）**平均情况**：期望运行次数时的复杂度。

4）**均摊复杂度**：连续执行足够多次后，将最坏情况均摊到每次操作上的复杂度。

**递归算法的时间复杂度**

递归算法的复杂度分析方法：

$$T(n) = \begin{cases}O(1), & n \le c \\a \cdot T(n/b) + f(n), & n > c\end{cases}$$

递归总次数 × 每次递归调用内部的简单操作次数 = 递归算法的时间复杂度

### 1.3.2 空间复杂度

空间复杂度 S(n) 定义为该算法所耗费的存储空间，它是问题规模 n 的函数，记为：

$$S(n) = O(g(n))$$

若算法执行时所需要的辅助空间相对于输入数据量而言是个常数，则称此算法为**原地工作**，空间复杂度为 O(1)。

常见的空间复杂度有 O(1)、O(n)、O(n²) 等。

**注意区分以下概念：**

* 输入数据本身占用的空间（不属于算法的空间复杂度）
* 算法执行过程中需要的辅助空间（属于算法的空间复杂度）
* 指令/常数变量等固定空间（通常忽略不计）

# 第二章 线性表

## 2.1 线性表的定义和基本操作

### 2.1.1 线性表的定义

线性表是具有相同数据类型的 n（n ≥ 0）个数据元素的有限序列。其中 n 为表长，当 n = 0 时线性表是一个空表。若用 L 命名线性表，则其一般表示为：

$$L = (a_1, a_2, \ldots, a_i, a_{i+1}, \ldots, a_n)$$

表中 $a_{i-1}$ 领先于 $a_i$，$a_i$ 领先于 $a_{i+1}$，称 $a_{i-1}$ 是 $a_i$ 的**直接前驱**，$a_{i+1}$ 是 $a_i$ 的**直接后继**。

线性表的特点：

* 表中元素个数有限
* 表中元素具有逻辑上的顺序性，表中元素有其先后次序
* 表中元素都是数据元素，每一个单个元素
* 表中元素的数据类型都相同，这意味着每个元素占有相同大小的存储空间
* 表中元素具有抽象性，即仅讨论元素间的逻辑关系，不考虑元素究竟表示什么内容

### 2.1.2 线性表的基本操作

一个数据结构的基本操作是指其最核心、最基本的操作。其他较复杂的操作可以通过调用基本操作来实现。线性表的主要操作如下：
    InitList(&L);           // 初始化表。构造一个空的线性表L
    Length(L);              // 求表长。返回线性表L的长度，即L中数据元素的个数
    LocateElem(L, e);       // 按值查找操作。在L中查找具有给定关键字值的元素
    GetElem(L, i);          // 按位查找操作。获取表L中第i个位置的元素的值
    ListInsert(&L, i, e);   // 插入操作。在表L中的第i个位置上插入指定元素e
    ListDelete(&L, i, &e);  // 删除操作。删除表L中第i个位置的元素，并用e返回删除元素的值
    PrintList(L);           // 输出操作。按前后顺序输出线性表L的所有元素值
    Empty(L);               // 判空操作。若L为空表，则返回true，否则返回false
    DestroyList(&L);        // 销毁操作。销毁线性表，并释放线性表L所占用的内存空间

## 2.2 线性表的顺序表示

### 2.2.1 顺序表的定义

线性表的顺序存储又称**顺序表**。它是用一组地址连续的存储单元依次存储线性表中的数据元素，从而使得逻辑上相邻的两个元素在物理位置上也相邻。

顺序表的特点：

* 随机访问，即通过首地址和元素序号可在时间 O(1) 内找到指定的元素
* 存储密度高，每个节点只存储数据元素
* 逻辑上相邻的元素物理上也相邻
* 插入和删除操作需要移动大量元素

顺序表的实现方式可以是一维数组，静态分配或动态分配：
    // 静态分配
    #define MaxSize 50        // 定义线性表的最大长度
    typedef struct {
        ElemType data[MaxSize]; // 顺序表的元素
        int length;             // 顺序表的当前长度
    } SqList;
    // 动态分配
    #define InitSize 100       // 表长度的初始定义
    typedef struct {
        ElemType *data;        // 指示动态分配数组的指针
        int MaxSize, length;   // 数组的最大容量和当前个数
    } SeqList;

动态分配的初始化：
    L.data = (ElemType *)malloc(sizeof(ElemType) * InitSize);

C语言中 `malloc` 函数用于动态申请内存空间，需要引入头文件 `<stdlib.h>` 和 `<malloc.h>`。`sizeof(ElemType)` 用于计算一个数据元素所需的内存大小，`InitSize` 表示初始申请的内存大小。

### 2.2.2 顺序表上基本操作的实现

**插入操作**

在顺序表 L 的第 i（1 ≤ i ≤ L.length + 1）个位置插入新元素 e。如果 i 的输入不合法，则返回 false，表示插入失败；否则，将顺序表的第 i 个元素及其后的所有元素右移一个位置，腾出一个空位插入新元素 e，顺序表长度加 1，插入成功，返回 true。
    bool ListInsert(SqList *L, int i, ElemType e) {
        if (i < 1 || i > L->length + 1)    // 判断i的范围是否有效
            return false;
        if (L->length >= MaxSize)         // 当前存储空间已满，不能插入
            return false;
        for (int j = L->length; j >= i; j--)
            L->data[j] = L->data[j - 1];  // 将第i个元素及之后的元素后移
        L->data[i - 1] = e;               // 在位置i处放入e
        L->length++;                      // 线性表长度加1
        return true;
    }

**时间复杂度分析：**

* 最好情况：在表尾插入（i = n + 1），循环体执行 0 次，时间复杂度为 O(1)
* 最坏情况：在表头插入（i = 1），循环体执行 n 次，时间复杂度为 O(n)
* 平均情况：假设 pᵢ（在第 i 个位置插入的概率）= 1/(n+1)，循环体执行 n-i+1 次$$\sum_{i=1}^{n+1} p_i(n-i+1) = \frac{1}{n+1}\sum_{i=1}^{n+1}(n-i+1) = \frac{n}{2}$$平均时间复杂度为 O(n)

**删除操作**

删除顺序表 L 中第 i（1 ≤ i ≤ L.length）个位置的元素。如果 i 的输入不合法，则返回 false；否则，将被删元素赋给引用变量 e，并将第 i+1 个元素及之后的元素全部左移一位，返回 true。
    bool ListDelete(SqList *L, int i, ElemType *e) {
        if (i < 1 || i > L->length)         // 判断i的范围是否有效
            return false;
        *e = L->data[i - 1];                // 将被删除的元素赋给e
        for (int j = i; j < L->length; j++)
            L->data[j - 1] = L->data[j];   // 将第i个位置之后的元素前移
        L->length--;                        // 线性表长度减1
        return true;
    }

**时间复杂度分析：**

* 最好情况：删除表尾元素（i = n），循环 0 次，时间复杂度 O(1)
* 最坏情况：删除表头元素（i = 1），循环 n-1 次，时间复杂度 O(n)
* 平均情况：假设 pᵢ（删除第 i 个元素的概率）= 1/n，循环体执行 n-i 次$$\sum_{i=1}^{n} p_i(n-i) = \frac{1}{n}\sum_{i=1}^{n}(n-i) = \frac{n-1}{2}$$平均时间复杂度为 O(n)

**按值查找（顺序查找）**

在顺序表 L 中查找第一个值等于 e 的元素，并返回其位序。
    int LocateElem(SqList L, ElemType e) {
        for (int i = 0; i < L.length; i++)
            if (L.data[i] == e)
                return i + 1;     // 下标为i的元素值等于e，返回其位序i+1
        return 0;                 // 查找失败，返回0
    }

**时间复杂度分析：**

* 最好情况：查找的元素就在表头，仅需比较一次，时间复杂度 O(1)
* 最坏情况：查找的元素在表尾或不存在，需比较 n 次，时间复杂度 O(n)
* 平均情况：假设 pᵢ（查找第 i 个元素的概率）= 1/n，需比较 i 次$$\sum_{i=1}^{n} p_i \cdot i = \frac{n+1}{2}$$平均时间复杂度为 O(n)

## 2.3 线性表的链式表示

### 2.3.1 单链表的定义

单链表用一组任意的存储单元来存储线性表中的数据元素。每个结点除了存放数据元素外，还需要存储指向其后继结点的地址（指针）。

单链表结点类型描述：
    typedef struct LNode {      // 定义单链表结点类型
        ElemType data;          // 数据域
        struct LNode *next;     // 指针域
    } LNode, *LinkList;

利用单链表可以解决顺序表需要大量连续存储单元的缺点，但单链表失去了随机存取的优点。

**两种实现方式：**

1）带头结点的单链表：头结点的数据域可以不存储任何信息（或存储链表长度等信息），头结点的指针域指向线性表的第一个元素结点。
    // 初始化一个空的链表
    bool InitList(LinkList *L) {
        *L = NULL;              // 空表，暂时没有任何结点
        return true;
    }
    // 判断是否为空
    bool Empty(LinkList L) {
        return (L == NULL);
    }

2）不带头结点的单链表：
    // 初始化
    bool InitList(LinkList *L) {
        (*L) = (LNode *)malloc(sizeof(LNode));  // 分配一个头结点
        if (*L == NULL)          // 内存不足，分配失败
            return false;
        (*L)->next = NULL;       // 头结点之后暂时还没有结点
        return true;
    }
    // 判空
    bool Empty(LinkList L) {
        return (L->next == NULL);
    }

**重要区别：**

* 不带头结点时，写代码需要对第一个结点单独处理（对空表和非空表的操作需要不同的代码逻辑）
* 带头结点时，第一个结点和后续结点的操作统一，代码更简洁

### 2.3.2 单链表上基本操作的实现

**建立单链表——头插法**

从头插法建立单链表的思想是从一个空表开始，生成新结点，读取数据存放到新结点的数据域中，然后将新结点插入到当前链表的表头（头结点之后）。
    LinkList List_HeadInsert(LinkList *L) {  // 逆向建立单链表
        LNode *s;
        int x;
        *L = (LinkList)malloc(sizeof(LNode));  // 创建头结点
        (*L)->next = NULL;                     // 初始化为空链表
        scanf("%d", &x);                       // 输入结点的值
        while (x != 9999) {                    // 输入9999表示结束
            s = (LNode *)malloc(sizeof(LNode)); // 创建新结点
            s->data = x;
            s->next = (*L)->next;
            (*L)->next = s;                   // 将新结点插入表中，*L为头指针
            scanf("%d", &x);
        }
        return *L;
    }

头插法建立的单链表中，结点的输入顺序与链表中的逻辑顺序相反。关键步骤是 `s->next = L->next; L->next = s;`（注意顺序不能颠倒）。

**建立单链表——尾插法**

从尾插法建立单链表的思想是从一个空表开始，将新结点逐个插入到链表的尾部。为此必须增加一个尾指针 r，使其始终指向当前链表的尾结点。
    LinkList List_TailInsert(LinkList *L) {  // 正向建立单链表
        int x;
        *L = (LinkList)malloc(sizeof(LNode));  // 创建头结点
        LNode *s, *r = *L;                    // r为表尾指针
        scanf("%d", &x);                       // 输入结点的值
        while (x != 9999) {                    // 输入9999表示结束
            s = (LNode *)malloc(sizeof(LNode));
            s->data = x;
            r->next = s;
            r = s;                            // r指向新的表尾结点
            scanf("%d", &x);
        }
        r->next = NULL;                       // 尾结点指针置空
        return *L;
    }

**按序号查找结点值**

在单链表中从第一个结点出发，顺指针域 next 逐个往下搜索，直到找到第 i 个结点为止，否则返回最后一个结点指针域 NULL。
    LNode *GetElem(LinkList L, int i) {
        if (i < 0) return NULL;
        int j = 0;                  // 当前p指向的是第几个结点
        LNode *p = L;              // L指向头结点，头结点是第0个结点（若有）
        while (p && j < i) {       // 循环找到第i个结点
            p = p->next;
            j++;
        }
        return p;                  // 返回第i个结点的指针，如果i大于表长则返回NULL
    }

**按值查找表结点**

从单链表第一个结点开始，由前往后依次比较各结点数据域的值，若某结点数据域的值等于给定值 e，则返回该结点的指针；若整个单链表中没有这样的结点，则返回 NULL。
    LNode *LocateElem(LinkList L, ElemType e) {
        LNode *p = L->next;       // p指向首元结点
        while (p != NULL && p->data != e)  // 从第1个结点开始查找数据域为e的结点
            p = p->next;
        return p;                  // 找到后返回该结点指针，否则返回NULL
    }

**插入结点操作**

将值为 x 的新结点 s 插入到单链表 L 的第 i 个位置上。先检查插入位置的合法性，然后找到待插入位置的前驱结点（即第 i-1 个结点 p），令新结点 s 的指针域指向 p 的后继结点，再令 p 的指针域指向新结点 s。
    // 后插操作：在p结点之后插入元素e
    bool InsertNextNode(LNode *p, ElemType e) {
        if (!p) return false;
        LNode *s = (LNode *)malloc(sizeof(LNode));
        if (!s) return false;            // 内存分配失败
        s->data = e;                    // 用结点s保存数据元素e
        s->next = p->next;
        p->next = s;                    // 将结点s连接到p之后
        return true;
    }
    // 前插操作：在p结点之前插入元素e（利用后插操作实现）
    bool InsertPriorNode(LNode *p, ElemType e) {
        if (!p) return false;
        LNode *s = (LNode *)malloc(sizeof(LNode));
        if (!s) return false;
        s->next = p->next;
        p->next = s;                    // 新结点s连到p之后
        s->data = p->data;             // 将p中数据元素放入到s中
        p->data = e;                   // 将e放入到p中
        return true;                   // 相当于s和p的数据交换
    }

**删除结点操作**

将单链表 L 的第 i 个结点删除。先检查删除位置的合法性，然后找到待删结点的前驱（即第 i-1 个结点 p），临时保存被删结点的值以备释放，再将 p 的指针域指向被删结点的后继，最后释放被删结点的空间。
    // 删除指定结点p（利用删除后继结点 trick 实现）
    bool DeleteNode(LNode *p) {
        if (!p) return false;
        LNode *q = p->next;           // 令q指向*p的后继结点
        p->data = q->data;            // 和后继结点交换数据域
        p->next = q->next;            // 将*q结点从链中断开
        free(q);                      // 释放后继结点的存储空间
        return true;
    }

**求表长操作**

计算单链表 L 中数据结点（不含头结点）的个数，从首元结点开始依次计数。
    int Length(LinkList L) {
        int len = 0;                  // 统计表长
        LNode *p = L;
        while (p->next) {
            p = p->next;
            len++;
        }
        return len;
    }

### 2.3.3 双链表

双链表是在单链表的每个结点中增加了一个指向其前驱的指针域 prior。这样形成的链表中有两个方向不同的链，故称之为双链表。

双链表结点类型描述：
    typedef struct DNode {           // 定义双链表结点类型
        ElemType data;               // 数据域
        struct DNode *prior, *next;  // 前驱和后继指针域
    } DNode, *DLinkList;

**双链表的插入操作**

在 p 结点之后插入 s 结点：
    s->next = p->next;    // ① 将结点*s插入到结点*p之后
    p->next->prior = s;   // ② 修改*p的后继结点的prior指针
    s->prior = p;         // ③ 修改*s的prior指针
    p->next = s;          // ④ 修改*p的next指针

**注意：** ①和④必须在②之前，否则 p 的后继结点的信息就丢了。

**双链表的删除操作**

删除 p 结点的后继结点 q：
    p->next = q->next;    // ① 断开*q与后续结点的链接
    q->next->prior = p;   // ② 修改后续结点的prior指针
    free(q);              // ③ 释放*q结点的空间

### 2.3.4 循环链表

**循环单链表**：最后一个结点的指针不是 NULL，而是指向头结点。整个链表形成一个环。从表中任一结点出发均可找到表中其他结点。

判断循环单链表为空的条件是：头结点的 next 是否等于头结点本身（L->next == L）。

**循环双链表**：当循环双链表为空时，L->prior 和 L->next 都等于 L。

循环链表的操作和普通链表类似，区别在于：

* 判断条件不同：循环链表中判断 p 是否走到表尾的条件是 `p->next != L`（而不是 `p->next != NULL`）
* 循环链表可以从任意结点出发遍历整个链表

### 2.3.5 静态链表

静态链表是用数组的方式来描述链表。数组中的每个元素包含两个部分：数据域 data 和指针域 next（这里的"指针"是下一个元素的数组下标，也称游标）。

静态链表结点类型描述：
    #define MaxSize 50              // 静态链表的最大长度
    typedef struct {
        ElemType data;              // 存储数据元素
        int next;                   // 下一个元素的数组下标（游标）
    } SLinkList[MaxSize];

静态链表以 `next == 0` 作为其结束的标志。静态链表的插入、删除操作与动态链表相同，只需要修改指针（游标），不需要移动元素。

**特点：**

* 优点：在插入和删除操作时，只需要修改游标，不需要移动元素，从而改进了在顺序表中插入和删除操作需要移动大量元素的缺点
* 缺点：没有解决连续存储分配带来的表长难以确定的问题
* 失去了顺序表随机存取的特性

## 2.4 顺序表和链表的比较

### 2.4.1 存取方式

* 顺序表可以**顺序存取**，也可以**随机存取**（存取时间性能为 O(1)）
* 链表只能从表头**顺序存取**（存取时间性能为 O(n)）

### 2.4.2 逻辑结构与物理结构

* 顺序表：逻辑上相邻的元素，物理存储位置也相邻。采用**预分配**的存储结构
* 链表：逻辑上相邻的元素，物理存储位置不一定相邻。采用**动态分配**的存储结构

### 2.4.3 查找、插入和删除操作

* **按值查找**：当无序时，两者时间复杂度均为 O(n)；当有序时，可采用折半查找，此时顺序表的时间复杂度为 O(log₂n)
* **按位查找**：顺序表支持随机访问，时间复杂度为 O(1)；链表平均需要 O(n)
* **插入和删除**：顺序表需要移动大量元素，平均 O(n)；链表只需修改指针，但查找位置仍需 O(n)

### 2.4.4 空间分配

* 顺序表：静态分配，在程序执行之前必须明确规定存储规模。若线性表长度变化较大，则存储规模难以预先确定，估计过大会造成空间浪费，估计过小会造成溢出
* 链表：动态分配，只要内存空间尚有空闲，就不会产生溢出

**选择依据：**

1. 基于存储的考虑：难以估计规模或存储规模波动较大 → 宜采用链表
2. 基于时间的考虑（主要考虑查找）：频繁按位存取 → 宜采用顺序表
3. 基于时间的考虑（主要考虑插入/删除）：频繁做插入/删除 → 宜采用链表
4. 基于环境的考虑：C/C++ 语言可用指针实现链表；Java 等面向对象语言中可用引用实现

# 第三章 栈和队列

## 3.1 栈

### 3.1.1 栈的基本概念

栈（Stack）是只允许在一端进行插入或删除操作的线性表。栈是一种**限定性**的线性表。

* 栈顶（Top）：线性表允许进行插入和删除的那一端
* 栈底（Bottom）：固定的，不允许进行插入和删除的另一端
* 空栈：不含任何元素的空表

栈的特点：**后进先出**（Last In First Out, LIFO）

栈的基本操作：
    InitStack(&S);          // 初始化一个空栈S
    StackEmpty(S);          // 判断一个栈是否为空
    Push(&S, x);            // 进栈，若栈S未满，则将x加入使之成为新栈顶
    Pop(&S, &x);            // 出栈，若栈S非空，则弹出栈顶元素，并用x返回
    GetTop(S, &x);          // 读栈顶元素，若栈S非空，则用x返回栈顶元素
    ClearStack(&S);         // 销毁栈，并释放栈S占用的存储空间

### 3.1.2 栈的顺序存储结构

**顺序栈**的实现：
    #define MaxSize 50
    typedef struct {
        ElemType data[MaxSize];  // 存放栈中元素
        int top;                 // 栈顶指针
    } SqStack;

约定栈顶指针 top 初始设置为 -1（即 top 指向当前栈顶元素的位置）；也有设置 top = 0 的方案（top 指向栈顶元素的下一位置）。

**栈的基本操作：**
    // 初始化
    void InitStack(SqStack *S) {
        S->top = -1;             // 初始化栈顶指针
    }
    // 判空
    bool StackEmpty(SqStack S) {
        if (S->top == -1) return true;
        else return false;
    }
    // 进栈
    bool Push(SqStack *S, ElemType x) {
        if (S->top == MaxSize - 1) return false;  // 栈满，报错
        S->data[++S->top] = x;                   // 指针先加1，再入栈
        return true;
    }
    // 出栈
    bool Pop(SqStack *S, ElemType *x) {
        if (S->top == -1) return false;           // 栈空，报错
        *x = S->data[S->top--];                  // 先出栈，指针再减1
        return true;
    }

    // 读栈顶元素
    bool GetTop(SqStack S, ElemType *x) {
        if (S->top == -1) return false;            // 栈空，报错
        *x = S.data[S.top];                      // x记录栈顶元素
        return true;
    }

**共享栈**：利用栈底位置相对不变的特性，可以让两个顺序栈共享一个一维数组空间。两个栈的栈底分别设在共享空间的两端，栈顶向共享空间的中间延伸。
    typedef struct {
        ElemType data[MaxSize];
        int top0;                // 0号栈栈顶指针
        int top1;                // 1号栈栈顶指针
    } ShStack;
    // 初始化
    void InitShStack(ShStack *S) {
        S->top0 = -1;            // 0号栈初始化栈顶指针
        S->top1 = MaxSize;       // 1号栈初始化栈顶指针
    }

共享栈只有在两个栈的栈顶相遇时才会发生上溢，因此比两个独立的顺序栈更节省空间。

### 3.1.3 栈的链式存储结构

**链栈**的实现：
    typedef struct LinkNode {
        ElemType data;
        struct LinkNode *next;
    } LinkNode, *LiStack;

链栈的优点是便于多个栈共享存储空间和提高效率，且不存在栈满上溢的情况。通常采用**单链表**实现，并规定所有操作都是在单链表的表头进行的（即链栈的栈顶就是链表的表头）。
    // 初始化
    void InitStack(LiStack *S) {
        *S = NULL;
    }
    // 判空
    bool StackEmpty(LiStack S) {
        if (S == NULL) return true;
        else return false;
    }
    // 进栈
    void Push(LiStack *S, ElemType x) {
        LinkNode *s = (LinkNode *)malloc(sizeof(LinkNode));
        s->data = x;
        s->next = *S;            // 新结点插入到栈顶
        *S = s;                  // 修改栈顶指针
    }
    // 出栈（栈非空才能出栈）
    bool Pop(LiStack *S, ElemType *x) {
        if (*S == NULL) return false;
        LinkNode *p = *S;
        *x = p->data;
        *S = p->next;
        free(p);
        return true;
    }

### 3.1.4 栈的应用

**括号匹配问题**

使用栈来检测表达式中的括号是否匹配。遇到左括号就进栈，遇到右括号就让栈顶元素出栈与之匹配。最后若栈空，则匹配成功。

**表达式求值（中缀转后缀）**

使用栈将中缀表达式转换为后缀表达式（逆波兰表达式）：

* 从左到右扫描中缀表达式
* 遇到操作数：直接加入后缀表达式
* 遇到运算符：
  * 若为 '(' ：入栈
  * 若为 ')' ：依次弹出栈顶运算符并加入后缀表达式，直到弹出 '(' 为止
  * 若为其他运算符：当栈不为空且栈顶运算符优先级不低于该运算符时，弹出栈顶运算符加入后缀表达式；将该运算符入栈

**递归**

递归调用本质上使用了系统栈。每次递归调用时，系统会把当前的局部变量、返回地址等压入栈中；递归返回时，从栈顶弹出保存的信息。

**深度优先搜索（DFS）**

图的深度优先遍历使用栈来保存待访问的节点路径。

## 3.2 队列

### 3.2.1 队列的基本概念

队列（Queue）是一种**先进先出**（First In First Out, FIFO）的线性表。它只允许在表的一端进行插入（入队），而在另一端进行删除（出队）。

* 队头（Front）：允许删除的一端，又称队首
* 队尾（Rear）：允许插入的一端
* 空队列：不含任何元素的空表

队列的基本操作：
    InitQueue(&Q);          // 初始化队列，构造一个空队列Q
    QueueEmpty(Q);          // 判队列空，若队列Q为空则返回true，否则false
    EnQueue(&Q, x);         // 入队，若队列Q未满，将x加入，使之成为新的队尾
    DeQueue(&Q, &x);        // 出队，若队列Q非空，删除队头元素，并用x返回
    GetHead(Q, &x);         // 读队头元素，若队列Q非空则将队头元素赋值给x

### 3.2.2 队列的顺序存储结构

**队列的顺序实现：**
    #define MaxSize 50
    typedef struct {
        ElemType data[MaxSize];  // 存放队列元素
        int front, rear;         // 队头指针和队尾指针
    } SqQueue;

**初始状态（队空条件）**：Q.front == Q.rear == 0

**进队操作**：队不满时，先送值到队尾元素，再将队尾指针加 1

**出队操作**：队不空时，先取队头元素值，再将队头指针加 1

**循环队列**：为了解决顺序队列的"假溢出"问题（队尾指针已到数组末尾但队列前面有空位），将存储队列的数组看成是环形的。
    // 初始化
    void InitQueue(SqQueue *Q) {
        Q->rear = Q->front = 0;
    }
    // 判空
    bool QueueEmpty(SqQueue Q) {
        if (Q.rear == Q.front) return true;
        else return false;
    }
    // 入队
    bool EnQueue(SqQueue *Q, ElemType x) {
        if ((Q->rear + 1) % MaxSize == Q->front) return false;  // 队满
        Q->data[Q->rear] = x;
        Q->rear = (Q->rear + 1) % MaxSize;                     // 队尾指针加1取模
        return true;
    }
    // 出队
    bool DeQueue(SqQueue *Q, ElemType *x) {
        if (Q->rear == Q->front) return false;                   // 队空
        *x = Q->data[Q->front];
        Q->front = (Q->front + 1) % MaxSize;                    // 队头指针加1取模
        return true;
    }

**循环队列判队满的方法：**

1）牺牲一个单元来区分队空和队满：入队时少用一个队列单元。队满条件：(Q.rear + 1) % MaxSize == Q.front

2）增设 size 变量：专门存储队列元素个数。队空条件：size == 0；队满条件：size == MaxSize

3）增设 tag 变量：每次入队操作成功时 tag = 1；每次出队操作成功时 tag = 0。队空条件：front == rear && tag == 0；队满条件：front == rear && tag == 1

### 3.2.3 队列的链式存储结构

**链队列**的实现：
    typedef struct LinkNode {        // 链式队列结点
        ElemType data;
        struct LinkNode *next;
    } LinkNode;
    typedef struct {                 // 链式队列
        LinkNode *front, *rear;      // 队头和队尾指针
    } LiQueue;

当 Q.front == NULL 且 Q.rear == NULL 时，链队列为空。
    // 初始化
    void InitQueue(LiQueue *Q) {
        Q->front = Q->rear = NULL;
    }
    // 判空
    bool QueueEmpty(LiQueue Q) {
        if (Q->front == NULL) return true;
        else return false;
    }
    // 入队
    void EnQueue(LiQueue *Q, ElemType x) {
        LinkNode *s = (LinkNode *)malloc(sizeof(LinkNode));
        s->data = x;
        s->next = NULL;
        if (Q->front == NULL)       // 在空队列中插入第一个元素
            Q->front = Q->rear = s;
        else {
            Q->rear->next = s;      // 新结点插入到rear之后
            Q->rear = s;            // 修改尾指针
        }
    }
    // 出队
    bool DeQueue(LiQueue *Q, ElemType *x) {
        if (Q->front == NULL) return false;   // 空队
        LinkNode *p = Q->front;
        *x = p->data;
        Q->front = p->next;
        if (Q->rear == p)          // 若原队列只有一个结点，出队后为空
            Q->rear = NULL;
        free(p);
        return true;
    }

链队列的优点是不存在队满上溢的情况（除非内存不足），便于实现多队列共享。

### 3.2.4 双端队列

双端队列（Deque）是允许两端都可以进行入队和出队操作的队列。其元素的逻辑结构仍是线性结构。

* **输出受限的双端队列**：允许在一端进行插入和删除，但在另一端只允许插入的双端队列
* **输入受限的双端队列**：允许在一端进行插入和删除，但在另一端只允许删除的双端队列

验证某个输出序列是否可能是双端队列的合法输出序列时，可以用模拟的方法逐一检验。

### 3.2.5 队列的应用

**层次遍历（BFS）**

二叉树的层序遍历和图的广度优先搜索都使用队列来实现。算法思想：1）根结点入队2）若队空，结束遍历；否则队头元素出队并访问3）若该元素有左孩子，则左孩子入队4）若该元素有右孩子，则右孩子入队5）回到步骤 2）

**缓冲区**

操作系统中的进程调度常使用队列作为缓冲区，用于解决主机与外设之间速度不匹配的问题。

**其他应用**：

* CPU 的任务调度
* 打印机的打印任务管理
* 网络请求的处理

# 第四章 树

## 4.1 树的基本概念

### 4.1.1 树的定义

树是 n（n ≥ 0）个结点的有限集合。当 n = 0 时，称为空树。在任意一棵非空树中应满足：1）有且仅有一个特定的称为**根**（Root）的结点2）当 n > 1 时，其余结点可分为 m（m > 0）个互不相交的有限集合 T₁, T₂, …, Tₘ，其中每个集合本身又是一棵树，并且称为根的**子树**（SubTree）

树是一种**递归**定义的数据结构。

### 4.1.2 基本术语

**结点相关术语：**

* **结点**：包含一个数据元素及若干指向其子树的分支
* **结点的度**：结点拥有的子树个数称为结点的度
* **树的度**：树内各结点的度的最大值
* **叶子（终端结点）**：度为 0 的结点
* **分支结点（非终端结点）**：度大于 0 的结点
* **内部结点**：度不为 0 且不为根的结点
* **父结点（双亲结点）**：一个结点的直接上层结点
* **子结点（孩子结点）**：一个结点的直接下层结点
* **兄弟结点**：同一父结点的子结点
* **堂兄弟**：双亲在同一层的结点
* **祖先**：从根到某结点路径上的所有结点
* **子孙**：以某结点为根的子树中的任一结点

**层次相关术语：**

* **结点的层数（深度）**：规定根结点在第 1 层，它的孩子（若有）在第 2 层……
* **树的高度（深度）**：树中结点的最大层数
* **有序树**：树中结点的各子树从左到右是有次序的，不能互换
* **无序树**：树中结点的各子树从左到右是无次序的，可以互换
* **森林**：m（m ≥ 0）棵互不相交的树的集合

### 4.1.3 树的性质

性质 1：树中的结点数等于所有结点的度数加 1。

性质 2：度为 m 的树中第 i 层上至多有 m^(i−1) 个结点（i ≥ 1）。

性质 3：高度为 h 的 m 叉树至多有 (m^h − 1)/(m − 1) 个结点。

性质 4：具有 n 个结点的 m 叉树的最小高度为 ⌈logₘ[n(m − 1) + 1]⌉。

## 4.2 二叉树

### 4.2.1 二叉树的定义与特性

**二叉树**是一种每个结点至多只有两棵子树（即二叉树中不存在度大于 2 的结点）的树结构。二叉树的子树有左右之分，其次序不能颠倒。

**五种基本形态：**

1. 空二叉树
2. 只有根结点
3. 根结点只有左子树
4. 根结点只有右子树
5. 根结点既有左子树又有右子树

**几个特殊的二叉树：**

1）**满二叉树**：一棵高度为 h，且含有 2^h − 1 个结点的二叉树称为满二叉树。每一层上的结点数都是最大结点数。

2）**完全二叉树**：高度为 h、有 n 个结点的二叉树，当且仅当其每个结点都与高度为 h 的满二叉树中编号为 1～n 的结点一一对应时，称为完全二叉树。

特点：

* 若 i ≤ ⌊n/2⌋，则结点 i 为分支结点，否则为叶子结点
* 叶子结点只可能在层次最大的两层上出现
* 若有度为 1 的结点，则只可能有一个，且该结点只有左孩子而无右孩子
* 一旦按层序编号，结点 i 的左孩子为 2i，右孩子为 2i+1，父结点为 ⌊i/2⌋

3）**二叉排序树（BST）**：左子树上所有结点的关键字均小于根结点的关键字；右子树上所有结点的关键字均大于根结点的关键字；左子树和右子树又分别是一棵二叉排序树。

4）**平衡二叉树（AVL树）**：树上任一结点的左子树和右子树的高度之差不超过 1。

### 4.2.2 二叉树的性质

性质 1：非空二叉树上的叶子结点数等于度为 2 的结点数加 1，即 n₀ = n₂ + 1。

证明：设二叉树中度为 0、1、2 的结点个数分别为 n₀、n₁、n₂，总结点数为 n，则：

* n = n₀ + n₁ + n₂ （总结点数）
* n = n₁ + 2·n₂ + 1 （边数 = 总结点数 − 1）联立得：n₀ = n₂ + 1

性质 2：非空完全二叉树按层序编号后，第 i 个结点（1 ≤ i ≤ n）：

* 其父结点编号为 ⌊i/2⌋（i = 1 时为根，无双亲）
* 若 2i ≤ n，则左孩子编号为 2i；否则无左孩子
* 若 2i + 1 ≤ n，则右孩子编号为 2i + 1；否则无右孩子

性质 3：具有 n 个（n > 0）个结点的完全二叉树的高度为 ⌈log₂(n + 1)⌉ 或 ⌊log₂n⌋ + 1。

性质 4：对于完全二叉树，可以由一层一层的结点数之和来推算给定 n 个结点的完全二叉树的高度 h：$$2^{h-1} - 1 < n \le 2^h - 1$$解得：h = ⌊log₂n⌋ + 1 = ⌈log₂(n + 1)⌉

### 4.2.3 二叉树的存储结构

**顺序存储结构**：

用一组地址连续的存储单元依次自上而下、自左至右存储完全二叉树中的结点元素。对于一般的二叉树，让其每个结点与完全二叉树上的结点相对应，存储在不存在的结点位置处设为"^"。
    #define MaxSize 100
    struct TreeNode {
        ElemType value;
        bool isEmpty;            // 结点是否为空
    };
    TreeNode t[MaxSize];         // 用数组存储二叉树

**链式存储结构**：
    // 二叉链表
    typedef struct BiTNode {
        ElemType data;                   // 数据域
        struct BiTNode *lchild, *rchild; // 左、右孩子指针
    } BiTNode, *BiTree;
    // 三叉链表（增加了父结点指针）
    typedef struct TriTNode {
        ElemType data;
        struct TriTNode *lchild, *rchild, *parent;
    } TriTNode, *TriTree;

n 个结点的二叉链表中有 n + 1 个空链域（可用于构造线索二叉树）。

### 4.2.4 二叉树的遍历

二叉树的遍历是指按照某条搜索路径访问树中的每个结点，使得每个结点均被访问一次，且仅被访问一次。

由于二叉树的递归特性，一棵非空的二叉树可以看作是由根结点、左子树和右子树三部分构成。只要依此遍历这三部分，就可遍历整棵二叉树。

**四种主要的遍历方式：**

1）**先序遍历（DLR）**：访问根结点 → 先序遍历左子树 → 先序遍历右子树
    void PreOrder(BiTree T) {
        if (T != NULL) {
            visit(T);              // 访问根结点
            PreOrder(T->lchild);  // 递归遍历左子树
            PreOrder(T->rchild);  // 递归遍历右子树
        }
    }

2）**中序遍历（LDR）**：中序遍历左子树 → 访问根结点 → 中序遍历右子树
    void InOrder(BiTree T) {
        if (T != NULL) {
            InOrder(T->lchild);
            visit(T);
            InOrder(T->rchild);
        }
    }

3）**后序遍历（LRD）**：后序遍历左子树 → 后序遍历右子树 → 访问根结点
    void PostOrder(BiTree T) {
        if (T != NULL) {
            PostOrder(T->lchild);
            PostOrder(T->rchild);
            visit(T);
        }
    }

4）**层序遍历**：从上到下、从左到右依次访问每个结点（基于队列实现）
    void LevelOrder(BiTree T) {
        InitQueue(Q);              // 初始化辅助队列
        BiTree p;
        EnQueue(Q, T);             // 根结点入队
        while (!IsEmpty(Q)) {
            DeQueue(Q, p);         // 队头结点出队
            visit(p);              // 访问出队结点
            if (p->lchild != NULL)
                EnQueue(Q, p->lchild);   // 左孩子入队
            if (p->rchild != NULL)
                EnQueue(Q, p->rchild);   // 右孩子入队
        }
    }

**由遍历序列构造二叉树：**

由二叉树的先序序列和中序序列可以唯一地确定一棵二叉树：

* 在先序序列中，第一个结点一定是二叉树的根
* 在中序序列中，根结点将序列分成左右两部分，左边是左子树的中序序列，右边是右子树的中序序列
* 递归地在左右子序列中应用同样的方法

同理，由后序序列和中序序列也可以唯一确定一棵二叉树。

**注意：** 由先序序列和后序序列不能唯一确定一棵二叉树（因为无法区分左右子树）。

### 4.2.5 线索二叉树

**线索二叉树的概念：**

遍历二叉树是以一定的规则将二叉树中的结点排列成一个线性序列，从而得到结点的前驱和后继信息。在具有 n 个结点的二叉链表中，共有 n + 1 个空指针域。利用这些空指针域存放指向结点在某种遍历次序下的前驱和后继信息，这种附加的指针称为**线索**，加上线索的二叉链表称为**线索链表**，相应的二叉树称为**线索二叉树**。

**线索的规定：**

* 若左孩子为空，则 lchild 指向前驱（ltag = 1）

* 若左孩子非空，则 lchild 指向左孩子（ltag = 0）

* 若右孩子为空，则 rchild 指向后继（rtag = 1）

* 若右孩子非空，则 rchild 指向右孩子（rtag = 0）
    typedef struct ThreadNode {
  
        ElemType data;
        struct ThreadNode *lchild, *rchild;
        int ltag, rtag;            // 左右线索标志
  
    } ThreadNode, *ThreadTree;

**中序线索二叉树的构造：**
    void InThread(ThreadTree &p, ThreadTree &pre) {
        if (p != NULL) {
            InThread(p->lchild, pre);   // 递归，线索化左子树
            if (p->lchild == NULL) {    // 左子树为空，建立前驱线索
                p->lchild = pre;
                p->ltag = 1;
            }
            if (pre != NULL && pre->rchild == NULL) {
                pre->rchild = p;         // 建立前驱结点的后继线索
                pre->rtag = 1;
            }
            pre = p;                    // 标记当前结点成为刚刚访问过的结点
            InThread(p->rchild, pre);   // 递归，线索化右子树
        }
    }

**在中序线索二叉树中找后继：**

* 若 rtag == 1，则 rchild 直接指向后继
* 若 rtag == 0（有右子树），后继为右子树中最左下的结点

**在中序线索二叉树中找前驱：**

* 若 ltag == 1，则 lchild 直接指向前驱
* 若 ltag == 0（有左子树），前驱为左子树中最右下的结点

## 4.3 树和森林

### 4.3.1 树的存储结构

**双亲表示法**：用一组连续空间存储树的结点，同时在每个结点中附设一个指示器指示其双亲结点在数组中的位置。
    #define MAX_TREE_SIZE 100
    typedef struct {
        ElemType data;           // 数据域
        int parent;              // 双亲位置域
    } PTNode;
    typedef struct {
        PTNode nodes[MAX_TREE_SIZE];  // 双亲数组
        int r, n;                     // 根的位置和结点数
    } PTree;

**孩子表示法**：将每个结点的孩子都用单链表链接起来，形成线性结构。n 个结点就有 n 个孩子链表（叶子结点的孩子链表为空链表）。

**孩子兄弟表示法（二叉树表示法）**：以二叉链表作为树的存储结构。每个结点包括三部分：数据域、第一个孩子指针域、右兄弟指针域。
    typedef struct CSNode {
        ElemType data;
        struct CSNode *firstchild, *nextsibling;  // 第一个孩子和右兄弟
    } CSNode, *CSTree;

这种存储方式便于实现各种树的操作，最重要的特点是：**任意一棵树都可以通过孩子兄弟表示法转换为一棵二叉树**。

### 4.3.2 树、森林与二叉树的转换

**树转换为二叉树：**1）加线：在所有兄弟结点之间加一条连线2）抹线：对每个结点，除了其左孩子外，去除其与其他孩子的连线3）旋转：以树的根结点为轴心，将树顺时针旋转 45°

规则：**左孩子右兄弟**——二叉树中结点的左孩子对应树中该结点的第一个孩子，二叉树中结点的右兄弟对应树中该结点的下一个兄弟。

**森林转换为二叉树：**1）将森林中的每棵树转换为二叉树2）第一棵二叉树不动，从第二棵二叉树开始，依次将后一棵二叉树的根结点作为前一棵二叉树根结点的右孩子

**二叉树转换为森林：**1）若二叉树非空，则二叉树的根及其左子树为第一棵树的二叉树形式2）二叉树的根的右子树可视为一个由除第一棵树外的剩余树转换而成的二叉树，应用同样的方法，直到最后产生一棵没有右子树的二叉树为止

### 4.3.3 树和森林的遍历

**树的遍历方式：**1）**先根遍历**：若树非空，先访问根结点，然后依次先根遍历每棵子树2）**后根遍历**：若树非空，则依次后根遍历每棵子树，最后访问根结点3）**层次遍历**：自上而下、自左至右访问树的每个结点

**森林的遍历方式：**1）**先序遍历**：访问森林中第一棵树的根结点 → 先序遍历第一棵树中根结点的子树森林 → 先序遍历除去第一棵树之后剩余的树构成的森林2）**中序遍历**：中序遍历森林中第一棵树的根结点的子树森林 → 访问第一棵树的根结点 → 中序遍历除去第一棵树之后剩余的树构成的森林

**对应关系：**

* 树的先根遍历 ↔ 对应二叉树的先序遍历
* 树的后根遍历 ↔ 对应二叉树的中序遍历
* 森林的先序遍历 ↔ 对应二叉树的先序遍历
* 森林的中序遍历 ↔ 对应二叉树的中序遍历

## 4.4 二叉排序树（BST）与平衡二叉树（AVL）

### 4.4.1 二叉排序树

**定义**：二叉排序树（又称二叉查找树）或者是一棵空树，或者是具有下列性质的二叉树：

* 若左子树非空，则左子树上所有结点的值均小于根结点的值
* 若右子树非空，则右子树上所有结点的值均大于根结点的值
* 左、右子树也分别是二叉排序树

**查找操作**：从根结点开始，若给定值等于根结点，则查找成功；若小于根结点，则在左子树中继续查找；若大于根结点，则在右子树中继续查找。

**插入操作**：若二叉排序树为空，则插入的结点为根结点；否则，继续在其左子树或右子树上查找，直到某个结点的左子树或右子树空为止，新结点将成为该结点的左孩子或右孩子。

**构造过程**：依次读入数据元素，将其插入到当前二叉排序树中的合适位置。

**删除操作分三种情况：**1）若被删结点 z 是叶结点：直接删除2）若被删结点 z 只有一棵子树：让 z 的子树成为 z 双亲的子树，替代 z 的位置3）若被删结点 z 有两棵子树：令 z 的直接后继（或直接前驱）替代 z，然后从二叉排序树中删去这个直接后继（或直接前驱）

**查找效率分析：**

* 含有 n 个结点的二叉排序树的平均查找长度与树的形态有关
* 最好情况：形态均匀（接近完全二叉树），ASL = O(log₂n)
* 最坏情况：退化为单支树（有序序列依次插入），ASL = O(n)

### 4.4.2 平衡二叉树（AVL树）

为了避免二叉排序树高度增长过快而导致查找性能降低，需要在二叉排序树的基础上引入平衡约束。

**定义**：平衡二叉树或者是空树，或者是满足下列性质的二叉排序树：

* 任一结点的左、右子树的高度差的绝对值不超过 1
* 左、右子树也都是平衡二叉树

**平衡因子（BF）**：结点的左子树高度减去右子树高度的值。平衡二叉树中所有结点的 BF ∈ {-1, 0, 1}。

**平衡调整（旋转）方法：**

每当插入一个结点时，首先检查插入路径上的结点是否失衡。若失衡，则找到最小不平衡子树进行调整。根据失衡原因的不同，有以下四种调整方式：

1）**LL 调整（右单旋）**：在结点 A 的左孩子（L）的左子树（L）上插入导致 A 失衡。将 A 的左孩子 B 向右上旋转代替 A 成为根，A 成为 B 的右孩子，B 的右子树成为 A 的左子树。

2）**RR 调整（左单旋）**：在结点 A 的右孩子（R）的右子树（R）上插入导致 A 失衡。将 A 的右孩子 B 向左上旋转代替 A 成为根，A 成为 B 的左孩子，B 的左子树成为 A 的右子树。

3）**LR 调整（先左后右双旋）**：在结点 A 的左孩子（L）的右子树（R）上插入导致 A 失衡。先将 A 的左孩子 B 的右孩子 C 向左上旋转代替 B，然后再将 C 向右上旋转代替 A。

4）**RL 调整（先右后左双旋）**：在结点 A 的右孩子（R）的左子树（L）上插入导致 A 失衡。先将 A 的右孩子 B 的左孩子 C 向右上旋转代替 B，然后再将 C 向左上旋转代替 A。

**AVL树的查找性能**：含有 n 个结点的平衡二叉树的最大深度为 O(log₂n)，因此平均查找长度也为 O(log₂n)。

**结论**：假设以 N_h 表示深度为 h 的平衡二叉树中含有的最少结点数。显然，N₀ = 0，N₁ = 1，N₂ = 2，并且有：

$$N_h = N_{h-1} + N_{h-2} + 1$$

这与斐波那契数列密切相关，由此可知 AVL 树的高度为 O(log₂n)。

## 4.5 哈夫曼树和哈夫曼编码

### 4.5.1 哈夫曼树的定义

**路径**：从树中一个结点到另一个结点之间的分支构成这两个结点之间的路径。

**路径长度**：路径上的分支数目。

**树的路径长度**：从树根到每个结点的路径长度之和。

**权**：树中结点赋予的一个具有某种含义的数值。

**带权路径长度（WPL）**：树中所有叶结点的带权路径长度之和。设二叉树有 n 个叶结点，每个叶结点带有权值 w_k，从根到叶结点 k 的路径长度为 l_k，则：

$$WPL = \sum_{k=1}^{n} w_k \cdot l_k$$

**哈夫曼树（最优二叉树）**：在含有 n 个带权叶结点的二叉树中，其中带权路径长度（WPL）最小的二叉树称为哈夫曼树（也称最优二叉树）。

### 4.5.2 哈夫曼树的构造

哈夫曼树的构造方法（哈夫曼算法）：1）将这 n 个结点分别作为 n 棵仅含一个结点的二叉树，构成森林 F2）构造一个新结点，从 F 中选取两棵根结点权值最小的树作为新结点的左、右孩子，并且将新结点的权值置为其左、右子树根结点的权值之和3）从 F 中删除刚才选出的两棵树，同时将新得到的树加入 F 中4）重复步骤 2）和 3），直至 F 中只剩下一棵树为止

**哈夫曼树的特点：**

* 每个初始结点最终都成为叶结点
* 权值越大的叶结点离根越近，权值越小的叶结点离根越远
* 构造过程中新建了 n − 1 个结点（分支结点），因此哈夫曼树中共有 2n − 1 个结点
* 哈夫曼树中不存在度为 1 的结点
* 哈夫曼树不唯一，但 WPL 一定相同且最小

### 4.5.3 哈夫曼编码

若没有一个编码是另一个编码的前缀，则称这样的编码为**前缀编码**。

哈夫曼编码是一种高效的前缀编码方案：1）统计每种字符在电文中出现的频率2）以每种字符的出现频率作为权值，构造哈夫曼树3）从根到每个叶子的路径上标记 0（左分支）和 1（右分支）4）将路径上的标记序列作为该字符的编码

**哈夫曼编码的特点：**

* 是前缀编码，保证了译码的唯一性
* 使用频率高的字符编码短，使用频率低的字符编码长，可使电文的总长度最短
* 没有两种不同字符的编码是完全相同的

# 第五章 图

## 5.1 图的基本概念

### 5.1.1 图的定义

图 G 由顶点集 V 和边集 E 组成，记为 G = (V, E)。其中 V(G) 表示图 G 中顶点的有限非空集；E(G) 表示图 G 中顶点之间的关系（边）的有限集合。

**有向图**：若 E 是有向边（也称弧）的有限集合，则图 G 为有向图。弧是顶点的有序对，记作 <v, w>，其中 v 称为弧尾，w 称为弧头。

**无向图**：若 E 是无向边的有限集合，则图 G 为无向图。边是顶点的无序对，记作 (v, w) 或 (w, v)。

**简单图**：既不存在重复边，也不存在顶点到自身的边的图。

**多重图**：图中两个顶点之间的边数多于一条，又允许顶点通过一条边与自身关联。

**完全图**：在无向完全图中，任意两个顶点之间都存在边，n 个顶点的无向完全图有 n(n−1)/2 条边。在有向完全图中，任意两个顶点之间都有方向相反的两条弧，n 个顶点的有向完全图有 n(n−1) 条弧。

**子图**：设有两个图 G = (V, E) 和 G' = (V', E')，若 V' ⊆ V 且 E' ⊆ E，则称 G' 为 G 的子图。

**连通、路径与回路：**

* **路径**：顶点 v_p 到 v_q 之间的一条路径是指顶点序列 v_p, v_{i1}, v_{i2}, …, v_{im}, v_q
* **回路（环）**：第一个顶点和最后一个顶点相同的路径
* **简单路径**：在路径序列中，顶点不重复出现的路径
* **简单回路**：除第一个顶点和最后一个顶点外，其余顶点不重复出现的回路
* **路径长度**：路径上边的数目
* **点到点的距离**：从顶点 u 到顶点 v 的最短路径长度。若 u 到 v 不可达，则距离为无穷大

**连通性相关术语：**

* **连通图**：在无向图中，若从顶点 v 到顶点 w 有路径存在，则称 v 和 w 是连通的。若图中任意两个顶点都是连通的，则称该图为连通图
* **连通分量**：无向图中的极大连通子图
* **强连通图**：在有向图中，若一对顶点 v 和 w，从 v 到 w 和从 w 到 v 都有路径，则称这两个顶点是强连通的。若图中任意一对顶点都是强连通的，则称该图为强连通图
* **强连通分量**：有向图中的极大强连通子树
* **生成树**：连通图的极小连通子图，包含图中全部 n 个顶点，但只有足以构成一棵树的 n−1 条边
* **生成森林**：非连通图中，每个连通分量的生成树构成了非连通图的生成森林

**度、入度和出度：**

* **度（TD）**：无向图中与该顶点相连的边的数目
* **入度（ID）**：有向图中以该顶点为终点的边的数目
* **出度（OD）**：有向图中以该顶点为起点的边的数目
* 关系：TD(v) = ID(v) + OD(v)
* 性质：<u>无向图中全部顶点的度的和等于边数的 2 倍</u>；<u>有向图中全部顶点的入度之和等于出度之和，且等于边数</u>

**网的定义**：带权的图称为网。边（或弧）上的权可以表示从一个顶点到另一个顶点的距离、花费或耗费等。

## 5.2 图的存储结构

### 5.2.1 邻接矩阵法

**基本思想**：用一个一维数组存储图中顶点的信息，用一个二维数组（称为邻接矩阵）存储图中各顶点之间的邻接关系。

若图 G 有 n 个顶点，则邻接矩阵是一个 n×n 的方阵，定义为：

$$arc[i][j] = \begin{cases}1, & \text{若 } (v_i, v_j) \text{ 或 } <v_i, v_j> \text{ 是 E(G) 中的边} \\0, & \text{否则}\end{cases}$$

对于带权图（网），邻接矩阵定义为：

$$arc[i][j] = \begin{cases}w_{ij}, & \text{若 } (v_i, v_j) \text{ 或 } <v_i, v_j> \text{ 是 E(G) 中的边} \\\infty, & \text{否则}\end{cases}$$

**邻接矩阵的特点：**

* 无向图的邻接矩阵是对称矩阵，可以采用压缩存储（只存储上三角或下三角部分）
* 对于无向图，邻接矩阵的第 i 行（或第 i 列）非零元素（或非∞元素）的个数正好是顶点 v_i 的度 TD(v_i)
* 对于有向图，第 i 行非零元素（或非∞元素）的个数是顶点 v_i 的出度 OD(v_i)；第 i 列非零元素（或非∞元素）的个数是顶点 v_i 的入度 ID(v_i)
* 非常适合判断两个顶点之间是否有边（或弧）；但确定图中有多少条边则需要扫描整个矩阵，时间复杂度为 O(n²)
* 稠密图适合使用邻接矩阵存储

**邻接矩阵的类型描述：**
    #define MaxVertexNum 100        // 顶点数目的最大值
    typedef char VertexType;        // 顶点的数据类型
    typedef int EdgeType;           // 带权图中边上权值的数据类型
    typedef struct {
        VertexType Vex[MaxVertexNUM];    // 顶点表
        EdgeType Edge[MaxVertexNum][MaxVertexNum];  // 邻接矩阵，边表
        int vexnum, arcnum;                 // 图的当前顶点数和弧数
    } MGraph;

### 5.2.2 邻接表法

**基本思想**：对图 G 中的每个顶点 v_i 建立一个单链表，第 i 个单链表中的结点表示依附于顶点 v_i 的边（对于有向图则是以 v_i 为尾的弧）。这种存储结构称为邻接表。

**邻接表中结点的结构：**
    // 边表结点
    typedef struct ArcNode {
        int adjvex;               // 该弧所指向的顶点的位置
        struct ArcNode *next;     // 指向下一条弧的指针
        // info                  // 网的权值等信息
    } ArcNode;
    // 顶点表结点
    typedef struct VNode {
        VertexType data;          // 顶点信息
        ArcNode *first;           // 指向第一条依附于该顶点的弧的指针
    } VNode, AdjList[MaxVertexNum];
    // 邻接表
    typedef struct {
        AdjList vertices;         // 邻接表
        int vexnum, arcnum;       // 图的顶点数和弧数
    } ALGraph;

**邻接表的特点：**

* 若 G 为无向图，则所需的存储空间为 O(|V| + 2|E|)；若 G 为有向图，则存储空间为 O(|V| + |E|)
* 对于无向图，邻接表中顶点 v_i 的度等于第 i 个单链表中的结点数
* 对于有向图，第 i 个单链表中的结点数是顶点 v_i 的出度；求 v_i 的入度需要遍历整个邻接表
* 适合存储稀疏图
* 给定顶点 v_i，要找出其所有邻接点，只需遍历第 i 个链表即可，时间复杂度为 O(1 + TD(v_i))

**注意**：在邻接表中，给定一个顶点，很容易求出它的所有邻接点；但要判断两个顶点 v_i 和 v_j 之间是否有边或弧，则需要搜索第 i 个或第 j 个链表，不如邻接矩阵方便。

### 5.2.3 十字链表（有向图）

十字链表是有向图的一种链式存储结构。结合了邻接表和逆邻接表的特点。

**结点结构：**

* 弧结点：tailvex（弧尾）、headvex（弧头）、hlink（同弧头的下一条弧）、tlink（同弧尾的下一条弧）、info（权值）
* 顶点结点：data（数据）、firstin（第一条入弧）、firstout（第一条出弧）

### 5.2.4 邻接多重表（无向图）

邻接多重表是无向图的一种链式存储结构。在邻接表中，每条边 (v_i, v_j) 会出现在两个链表中（v_i 的链表和 v_j 的链表），这在某些操作上不方便。邻接多重表解决了这个问题。

## 5.3 图的遍历

### 5.3.1 深度优先搜索（DFS）

**算法思想**：从图中某一顶点 v 出发，访问此顶点，然后从 v 的未被访问的邻接点出发深度优先遍历图，直至图中所有和 v 有路径相通的顶点都被访问到；若图中还有顶点未被访问，则另选图中一个未曾访问的顶点作起始点，重复上述过程，直至图中所有顶点都被访问到为止。

DFS 是一种"回溯"的搜索策略，可以用**递归**或**栈**来实现。
    bool visited[MAX_VERTEX_NUM];   // 访问标记数组
    void DFS(Graph G, int v) {
        visit(v);                   // 访问顶点v
        visited[v] = TRUE;          // 设已访问标记
        for (w = FirstNeighbor(G, v); w >= 0; w = NextNeighbor(G, v, w))
            if (!visited[w])       // w为u的尚未访问的邻接顶点
                DFS(G, w);         // 递归调用DFS
    }

**DFS 算法性能分析：**

* 邻接矩阵存储：时间复杂度为 O(|V|²)，空间复杂度为 O(|V|)
* 邻接表存储：时间复杂度为 O(|V| + |E|)，空间复杂度为 O(|V|)

### 5.3.2 广度优先搜索（BFS）

**算法思想**：类似于树的层序遍历。从图中某一顶点 v 出发，访问此顶点，然后依次访问 v 的各个未被访问的邻接点，再分别从这些邻接点出发依次访问它们的邻接点，且"先被访问的顶点的邻接点先于后被访问的顶点的邻接点被访问"，直到图中所有已被访问的顶点的邻接点都被访问到。

BFS 需要**队列**来辅助实现。
    bool visited[MAX_VERTEX_NUM];   // 访问标记数组
    void BFS(Graph G, int v) {
        visit(v);                   // 访问初始顶点v
        visited[v] = TRUE;          // 对v做已访问标记
        EnQueue(Q, v);              // 顶点v入队列Q
        while (!isEmpty(Q)) {
            DeQueue(Q, v);         // 顶点v出队
            for (w = FirstNeighbor(G, v); w >= 0; w = NextNeighbor(G, v, w))
                if (!visited[w]) { // w为v的尚未访问的邻接顶点
                    visit(w);      // 访问顶点w
                    visited[w] = TRUE; // 对w做已访问标记
                    EnQueue(Q, w); // 顶点w入队
                }
        }
    }

**BFS 算法性能分析：**

* 邻接矩阵存储：时间复杂度为 O(|V|²)，空间复杂度为 O(|V|)
* 邻接表存储：时间复杂度为 O(|V| + |E|)，空间复杂度为 O(|V|)

**BFS 求单源最短路径（无权图）：**BFS 算法可用于求解无权图的单源最短路径。这是因为 BFS 总是按照距离起始点由近到远的顺序来遍历图中的各个顶点。

### 5.3.3 图的连通性

**无向图的连通性：**

* 对无向图进行 DFS/BFS 遍历，调用 DFS/BFS 的次数就是连通分量的个数
* 要判断无向图 G 中任意两顶点 u 和 v 是否连通，可以对图 G 进行一次 DFS/BFS，看 u 和 v 是否都在同一个连通分量中

**有向图的连通性：**

* 有向图的连通性要更复杂一些
* 调用 DFS/BFS 的次数可以得到强连通分量的个数
* 可以通过对有向图及其反图（所有弧反向）分别进行 DFS 来求解强连通分量（Kosaraju 算法）

## 5.4 最小生成树

### 5.4.1 最小生成树的概念

对于一个带权无向连通图 G = (V, E)，生成树是包含图中全部顶点的一个极小连通子图。若图中各边带有权值，则所有生成树中总权值最小的那棵称为**最小生成树**（Minimum Spanning Tree, MST）。

最小生成树的性质：

* 最小生成树可能有多个，但它们的总权值一定相等且最小
* 最小生成树的边数 = 顶点数 − 1
* 最小生成树中添加任意一条不在树中的边，一定会形成环路

### 5.4.2 Prim 算法

**算法思想**（贪心策略）：从某一个顶点开始，每次选择与当前生成树中所有顶点相连的权值最小的边，将该边和对应的顶点加入到生成树中，直到所有顶点都加入到生成树中为止。

**算法过程：**1）初始化：U = {u₀}（u₀为起始顶点），TE = {}（TE为最小生成树的边集）2）在所有 u ∈ U, v ∈ V − U 的边 (u, v) ∈ E 中找一条权值最小的边 (u₀, v₀)3）将 (u₀, v₀) 加入 TE，v₀ 加入 U4）重复步骤 2）和 3），直到 U = V 为止

**时间复杂度**：O(|V|²)，适合稠密图。

### 5.4.3 Kruskal 算法

**算法思想**（贪心策略）：将图中所有的边按权值从小到大排序，然后从最小的边开始逐一考察。如果当前边与已选的边不构成回路，则将其选中；否则跳过。直到选出 |V| − 1 条边为止。

**算法过程：**1）将 G 中的各边按权值从小到大排序2）令生成树的边集 TE = {}，初始时每个顶点自成连通分量3）按权值从小到大逐条考查各边：

* 若该边连接的两个顶点属于不同的连通分量，则将该边加入 TE，合并这两个连通分量
* 否则舍弃该边4）重复步骤 3），直到 TE 中含有 |V| − 1 条边

**时间复杂度**：O(|E| log |E|)，适合稀疏图。通常使用**并查集**来判断两个顶点是否属于同一个连通分量。

## 5.5 最短路径

### 5.5.1 BFS 求无权图的单源最短路径

对于无权图（或每条边权值相同的图），可以使用 BFS 求解单源最短路径。因为 BFS 是按层次遍历的，第一次访问到某顶点时所经过的路径一定是最短的。

### 5.5.2 Dijkstra 算法（单源最短路径——带权图）

**适用条件**：带权有向图/无向图，**边权值必须非负**。

**算法思想**（贪心策略）：1）初始化：集合 S 存放已找到最短路径的顶点，初始 S = {源点 v₀}。对每个顶点 v_i，设置 dist[v_i] 为 v₀ 到 v_i 的当前最短路径长度2）从 V − S 中选取一个 dist 值最小的顶点 u，将其加入 S3）对 u 的所有邻接点 v 进行松弛操作：如果 dist[u] + w(u, v) < dist[v]，则更新 dist[v] = dist[u] + w(u, v)4）重复步骤 2）和 3），直到 S = V 为止

**时间复杂度**：O(|V|²)。若使用斐波那契堆优化，可达 O(|V| log |V| + |E|)。

**注意**：Dijkstra 算法**不适用于**含有负权边的图。

### 5.5.3 Floyd 算法（各顶点之间的最短路径）

**算法思想**（动态规划）：

设 A⁽⁻¹⁾[i][j] = arcs[i][j]（即初始邻接矩阵），然后进行 |V| 次迭代：

$$A^{(k)}[i][j] = \min\{A^{(k-1)}[i][j], A^{(k-1)}[i][k] + A^{(k-1)}[k][j]\}$$

含义：从 v_i 到 v_j 只经过编号不超过 k 的顶点的最短路径长度。

**时间复杂度**：O(|V|³)。空间复杂度：O(|V|²)。

Floyd 算法可以处理**负权边**（但不能处理负权回路）。





## 5.6 有向无环图及其应用



### 5.6.1 有向无环图（DAG）

若一个有向图中不存在环，则称为**有向无环图**（Directed Acyclic Graph, DAG）。

DAG 在工程规划和项目管理中有重要应用（如 AOV 网和 AOE 网）。

### 5.6.2 拓扑排序

**AOV 网**：用顶点表示活动，用弧表示活动之间的优先关系的有向图称为**顶点表示活动的网**（Activity On Vertex network, AOV 网）。

**拓扑排序**：将 AOV 网中的所有顶点排成一个线性序列，使得若图中存在从 v_i 到 v_j 的弧，则序列中 v_i 必须排在 v_j 之前。满足此性质的线性序列称为**拓扑有序序列**，简称**拓扑序列**。

**算法思想：**1）从有向图中选择一个**没有前驱**（入度为 0）的顶点并输出2）从图中删除该顶点和所有以它为尾的弧3）重复上述两步，直到全部顶点都已输出，或图中剩余顶点都有前驱（说明图中存在环）

**时间复杂度**：O(|V| + |E|)。可用**栈**或**队列**来保存入度为 0 的顶点。

**注意**：一个 DAG 的拓扑序列可能不唯一；若图中所有顶点都在拓扑序列中，则图中不存在有向环。

### 5.6.3 关键路径





**AOE 网**：用边表示活动，边上权值表示活动持续时间的有向图称为**边表示活动的网**（Activity On Edge network, AOE 网）。

**关键路径**：在 AOE 网中，从源点到汇点的最长路径称为**关键路径**。关键路径上的活动称为**关键活动**。关键活动的持续时间决定了整个工程的最早完成时间。

**相关概念：**

* **事件 v_i 的最早发生时间 ve(i)**：从源点到 v_i 的最长路径长度
* **事件 v_i 的最迟发生时间 vl(i)**：在不推迟整个工期的前提下，事件 v_i 允许的最迟发生时间
* **活动 a_k 的最早开始时间 e(k)**：等于该活动弧尾所对应事件的最早发生时间
* **活动 a_k 的最迟开始时间 l(k)**：等于该活动弧头所对应事件的最迟发生时间与该活动持续时间之差
* **关键活动**：满足 e(k) = l(k) 的活动，即没有时间余量的活动

**关键路径算法的时间复杂度**：O(|V| + |E|)。

# 第六章 查找

## 6.1 查找的基本概念

### 6.1.1 基本概念

**查找**：根据给定的某个值，在查找表中确定一个其关键字等于给定值的数据元素（或记录）。

**关键字**：数据元素中某个数据项的值，用以标识一个数据元素。

* **主关键字**：可以唯一标识一个记录的关键字
* **次关键字**：可以识别若干记录的关键字

**查找表**：由同一类型的数据元素（或记录）构成的集合。

* **静态查找表**：仅作查找操作的查找表。主要操作：查询某个特定的数据元素是否在表中；检索某个特定数据元素的各种属性
* **动态查找表**：在查找过程中同时插入查找表中不存在的数据元素，或者从查找表中删除已存在的数据元素

**平均查找长度（ASL）**：在查找过程中，需要比较关键字的期望次数，称为查找算法的平均查找长度。

$$ASL = \sum_{i=1}^{n} P_i \cdot C_i$$

其中 P_i 是查找第 i 个元素的概率，C_i 是找到第 i 个元素所需比较的次数。

## 6.2 顺序查找和折半查找

### 6.2.1 顺序查找

**算法思想**：从线性表的一端向另一端逐个比较关键字。若找到，则查找成功；若整个表都找完仍未找到，则查找失败。

**适用于**：顺序表和链表的**线性查找**。
    // 顺序查找（哨兵技术，减少循环中的判断次数）
    int SeqSearch(SSTable ST, ElemType key) {
        ST.elem[0] = key;          // 哨兵
        int i;
        for (i = ST.TableLen; ST.elem[i] != key; --i);  // 从后往前找
        return i;                  // 若找到，返回元素位置；若未找到，返回0
    }

**时间复杂度**：

* 查找成功：ASL_成功 = (n+1)/2，时间复杂度 O(n)
* 查找失败：ASL_失败 = n+1，时间复杂度 O(n)

**优点**：算法简单，对表结构无任何要求（顺序存储和链式存储均可），对记录是否有序也无要求。

**缺点**：平均查找长度较大，特别是当 n 很大时，查找效率较低。

### 6.2.2 折半查找（二分查找）

**适用条件**：**有序的顺序表**。

**算法思想**：将待查关键字与表中间位置的关键字进行比较，若相等则查找成功；若小于则在左半区继续查找；若大于则在右半区继续查找。不断重复这个过程，直到查找成功或确定查找失败。
    int Binary_Search(SSTable L, ElemType key) {
        int low = 1, high = L.TableLen, mid;
        while (low <= high) {
            mid = (low + high) / 2;
            if (L.elem[mid] == key)
                return mid;           // 查找成功
            else if (L.elem[mid] > key)
                high = mid - 1;       // 在左半区查找
            else
                low = mid + 1;        // 在右半区查找
        }
        return 0;                     // 查找失败
    }

**折半查找判定树**：折半查找的过程可以用一棵二叉树来描述，称为**判定树**。树中每个结点对应一个记录在表中的位置。

* 查找成功时的比较次数 = 该结点在判定树中的层次
* 查找失败时的比较次数 = 该叶子结点所在层次 − 1（或等于该虚结点的父结点所在层次）

**时间复杂度**：O(log₂n)

**ASL 分析**：

* 查找成功的 ASL ≈ log₂(n+1) − 1
* 查找失败的 ASL ≈ log₂(n+1)

**优点**：比较次数少，查找速度快，平均性能好。

**缺点**：要求有序顺序表，且插入删除困难（不适合动态变化的查找表）。

### 6.2.3 分块查找

**分块查找**又称**索引顺序查找**，是对顺序查找的一种改进。

**算法思想**：将查找表分成若干个子表（块）。子表内部不一定有序，但子表之间是有序的（前一块中的最大关键字小于后一块中的最小关键字）。另外，还建立一个**索引表**，索引表中每个元素含有各块的最大关键字和各块的起始地址。

**查找过程**：1）在索引表中确定待查记录所在的块（可以使用顺序查找或折半查找）2）在确定的块中进行顺序查找

**ASL 分析**：设长度为 n 的表均匀分成 b 块，每块 s 个元素。设索引查找和块内查找的平均查找长度分别为 L_b 和 L_w，则：

$$ASL = L_b + L_w$$

若用顺序查找索引表，则 L_b = (b+1)/2，L_w = (s+1)/2，ASL = (b+s+2)/2 = (n/s+s)/2 + 1

当 s = √n 时，ASL 取最小值 √n + 1。

## 6.3 树形查找

### 6.3.1 二叉排序树（BST）查找

已在第四章 4.4.1 节详细阐述。此处补充查找操作的完整实现：
    // 在二叉排序树中查找值为key的结点（递归实现）
    BiTNode *BST_Search(BiTree T, ElemType key) {
        if (T == NULL)
            return NULL;                        // 查找失败
        if (key == T->data)
            return T;                          // 查找成功
        else if (key < T->data)
            return BST_Search(T->lchild, key); // 在左子树中继续查找
        else
            return BST_Search(T->rchild, key); // 在右子树中继续查找
    }
    // 在二叉排序树中查找值为key的结点（非递归实现）
    BiTNode *BST_Search_NonRec(BiTree T, ElemType key) {
        while (T != NULL && key != T->data) {
            if (key < T->data)
                T = T->lchild;
            else
                T = T->rchild;
        }
        return T;
    }

### 6.3.2 平衡二叉树（AVL树）查找

已在第四章 4.4.2 节详细阐述。AVL 树的查找操作与 BST 相同，但由于 AVL 树保证了树的高度为 O(log₂n)，因此查找效率稳定在最坏情况下也是 O(log₂n)。

### 6.3.3 B 树和 B+ 树

#### B 树

**B 树**是一种平衡的多路查找树。2-3 树和 2-3-4 树都是 B 树的特例。我们把树中结点最大的孩子数目称为 B 树的阶，通常记为 m。

**一棵 m 阶 B 树**或为空树，或为满足如下特性的 m 叉树：

1）树中每个结点至多有 m 棵子树（即至多含有 m − 1 个关键字）（"两棵子树指针夹着一个关键字"）

2）若根结点不是终端结点，则至少有两棵子树（至少一个关键字）

3）除根结点外的所有非叶结点至少有 ⌈m/2⌉ 棵子树（即至少含有 ⌈m/2⌉ − 1 个关键字）

4）所有非叶结点的结构如下：

| n | P₀ | K₁ | P₁ | K₂ | ... | Kₙ | Pₙ |

其中 Ki (i = 1, 2, ..., n) 为结点的关键字，且满足 K₁ < K₂ < ... < Kₙ

其中 Pi (i = 0, 1, ..., n) 为指向子树根结点的指针，且指针 Pi−1 所指的子树的所有结点的关键字都小于 Ki，Pi 所指向子树的所有结点的关键字都小于 Ki+1

5）所有叶子结点出现在同一层次上，不带信息（就像是折半查找判断树中查找失败的结点）

**B 树的操作：**

**1. B 树的查找操作**

B 树是多路查找树，二叉排序树是二路查找，B 树是多路查找，所以它是二叉排序树的拓展。因此，B 树的查找操作和二叉排序树的查找操作非常类似。

查找过程：① 先让待查找关键字 key 和结点中的关键字比较，如果等于其中某个关键字，则查找成功② 如果和所有关键字都不相等，则看 key 处在哪个范围内，然后去对应的指针所指向的子树中查找

例如：如果 Key 比第一个关键字 K₁ 还小，则去 P₀ 指针所指向的子树中查找；如果比最后一个关键字 Kₙ 还大，则去 Pₙ 指针所指向的子树中查找。

**2. B 树的插入操作**

在二叉排序树中，仅需查找到需插入的终端结点的位置。但是，在 B 树中找到插入的位置后，并不能简单地将其添加到终端结点位置，因为此时可能会导致整棵树不再满足 B 树中定义中的要求。

**分裂的方法**：取这个关键字数组中的中间关键字（⌈n/2⌉）作为新的结点，然后其他关键字形成两个结点作为新结点的左右孩子。

**3. B 树的删除操作**

B 树中的删除操作与插入操作类似，但要稍微复杂些，要使得删除后的结点中的关键字个数 ≥ ⌈m/2⌉ − 1，因此将涉及结点的"合并"问题。由于删除的关键字位置不同，可以分为关键字在终端结点和不在终端结点上两种情况：

**情况 1：删除的关键字在终端结点上（最底层非叶子结点）**① 结点内关键字数量 > ⌈m/2⌉ − 1：直接删除② 结点内关键字数量 = ⌈m/2⌉ − 1，且其左右兄弟结点中存在关键字数量 > ⌈m/2⌉ − 1 的结点：去兄弟结点中借关键字③ 结点内关键字数量 = ⌈m/2⌉ − 1，且其左右兄弟结点中都不存在关键字数量 > ⌈m/2⌉ − 1 的结点：需要进行结点合并

**情况 2：删除的关键字不在终端结点上**

需要先转换成在终端结点上，再按照在终端结点上的情况来分别考虑对应的方法。

**相邻关键字**：对于不在终端结点上的关键字，它的相邻关键字是其左子树中值最大的关键字或者右子树中值最小的关键字。

* 第一种情况：存在关键字数量 > ⌈m/2⌉ − 1 的左子树或者右子树，在对应子树上找到该关键字的相邻关键字，然后将相邻关键字替换待删除的关键字
* 第二种情况：左右子树的关键字数量均 = ⌈m/2⌉ − 1，则将这两个左右子树结点合并，然后删除待删除关键字

#### B+ 树

**m 阶的 B+ 树与 m 阶的 B 树的主要差异在于：**

1）在 B+ 树中，具有 n 个关键字的结点只含有 n 棵子树，即每个关键字对应一棵子树；而在 B 树中，具有 n 个关键字的结点含有 (n+1) 棵子树

2）在 B+ 树中，每个结点（非根内部结点）关键字个数 n 的范围是 ⌈m/2⌉ ≤ n ≤ m（根结点 1 ≤ n ≤ m）；在 B 树中，每个结点（非根内部结点）关键字个数 n 的范围是 ⌈m/2⌉ − 1 ≤ n ≤ m − 1（根结点：1 ≤ n ≤ m − 1）

3）在 B+ 树中，叶结点包含信息，所有非叶结点仅起到索引作用，非叶结点中的每个索引项只含有对应子树的最大关键字和指向该子树的指针，不含有该关键字对应记录的存储地址

4）在 B+ 树中，叶结点包含了全部关键字，即在非叶结点中出现的关键字也会出现在叶结点中；而在 B 树中，叶结点包含的关键字和其他结点包含的关键字是不重复的

5）在 B+ 树中，有一个指针指向关键字最小的叶子结点，所有叶子结点链接成一个单链表

**B+ 树是常用于数据库和操作系统的文件系统中的一种用于查找的数据结构。**

## 6.4 散列表（哈希表）

### 6.4.1 散列表的基本概念

**散列表**：根据给定的关键字来计算出关键字在表中的地址的数据结构。也就是说，散列表建立了**关键字**和**存储地址**之间的一种直接映射关系。

散列函数可能会把两个或两个以上的不同关键字映射到同一地址，称这种情况为**"冲突"**，这些发生碰撞的不同关键字称为**同义词**。

**散列函数**：一个把查找表中的关键字映射成该关键字对应的地址的函数，记为 Hash(key) = Addr。

### 6.4.2 散列函数的构造方法



**散列函数的设计原则：**1）散列函数的定义域必须包含全部需要存储的关键字，而值域的范围则依赖于散列表的大小或地址范围2）散列函数计算出来的地址应该能等概率、均匀地分布在整个地址空间，从而减少冲突的发生3）散列函数应尽量简单，能够在较短的时间内就计算出任一关键字对应的散列地址

**常用散列函数构造方法：**

**1. 除留余数法**

假定散列表表长为 m，取一个不大于 m 但最接近或等于 m 的质数 p，利用以下公式把关键字转换成散列地址：

$$H(key) = key \% p$$

除留余数法的关键是选好 p，使得每一个关键字通过该函数转换后等概率地映射到散列空间上的任一地址，从而尽可能减少冲突的可能性。

**2. 数字分析法**

设关键字是 r 进制数（如十进制数），而 r 个数码在各位上出现的频率不一定相同，可能在某些位上分布均匀些，每种数码出现的机会均等；而在某些位上分布不均匀，只有某几种数码经常出现，则应选取数码分布较为均匀的若干位作为散列地址。这种方法适合于已知的关键字集合。

例如：某个公司的员工手机号码簿，后 4 位分布较为均匀，前 7 位分布不均匀甚至完全相同，则应选取后 4 位作为散列地址。

**3. 平方取中法**

顾名思义，取关键字的平方值的中间几位作为散列地址。具体取多少位要看实际情况而定。这种方法得到的散列地址与关键字的每一位都有关系，使得散列地址分布比较均匀。

例如：1234² = 1522756，取中间三位 227 作为散列地址；2345² = 5499025，取中间三位 990 作为散列地址。

**4. 折叠法**

将关键字分割成位数相同的几部分（最后一部分的位数可以短一些），然后取这几部分的叠加和作为散列地址。关键字位数很多，而且关键字中每一位上数字分布大致均匀时，可以采用折叠法得到散列地址。

例如：关键字为 1234567890，散列表表长为 3 位，可以将关键字分为四组每组 3 位：123 | 456 | 789 | 0，然后这四组叠加求和 123 + 456 + 789 + 0 = 1368，然后取后 3 位就能得到散列地址为 368。

### 6.4.3 处理冲突的方法

**1. 开放定址法**

将产生冲突的 Hash 地址作为自变量，通过某种冲突解决函数得到一个新的空闲的 Hash 地址。

**（1）线性探测法**

冲突发生时，顺序查看表中下一个单元（当探测到表尾地址 m − 1 时，下一个探测地址是表首地址 0），直到找出一个空闲单元（当表未填满时一定能找到一个空闲单元）或查遍全表。

$$H_i = (H(key) + d_i) \% m$$

其中 dᵢ = 1, 2, 3, ..., m − 1

**缺点**：线性探测法会造成大量元素在相邻的散列地址上"聚集"（或堆积）起来，大大降低了查找效率。

**（2）平方探测法（二次探测法）**

设发生冲突的地址为 d，平方探测法得到的新的地址序列为 d + 1², d − 1², d + 2², d − 2², ...

平方探测法是一种较好的处理冲突的方法，可以避免出现"堆积"问题，它的缺点是不能探测到散列表上的所有单元，但至少能探测到一半单元。

**（3）再散列法（双散列法）**

需要使用两个散列函数，当通过第一个散列函数 H(Key) 得到的地址发生冲突时，则利用第二个散列函数 Hash2(Key) 计算该关键字的地址增量。

$$H_i = (H(Key) + i \times Hash2(Key)) \% m$$

其中 m 是散列表长，i 是冲突次数，初值为 0。

**（4）伪随机序列法**

当发生地址冲突时，地址增量为伪随机数序列，称为伪随机序列法。

**2. 拉链法（链地址法）**

对于不同的关键字可能会通过散列函数映射到同一地址，为了避免非同义词发生冲突，可以把所有的同义词存储在一个线性链表中，这个线性链表由其散列地址唯一标识。拉链法适用于经常进行插入和删除的情况。

### 6.4.4 散列表的查找性能

**装填因子**：散列表的装填因子一般记为 α，定义为一个表的装满程度。

$$\alpha = \frac{\text{表中记录数 } n}{\text{散列表长度 } m}$$

散列表的平均查找长度依赖于散列表的填装因子 α，而不直接依赖于 n 或 m。

α 越大，表示装填的记录越"满"，发生冲突的可能性就越大；反之发生冲突的可能性越小。

**散列表的查找过程**：类似于构造散列表，给定一个关键字 Key：1）先根据散列函数计算出其散列地址2）然后检查散列地址位置有没有关键字

* 如果没有，表明该关键字不存在，返回查找失败
* 如果有，则检查该记录是否等于关键字
  * 如果等于关键字，返回查找成功
  * 如果不等于，则按照给定的冲突处理办法来计算下一个散列地址，再用该地址去执行上述过程

# 第七章 排序

## 7.1 排序的基本概念

### 7.1.1 排序的定义

**排序**：将一个数据元素（或记录）的任意序列重新排成一个按关键字有序的序列。

**排序的稳定性**：若待排序表中有两个元素 R_i 和 R_j，它们的关键字相等（K_i = K_j），且在排序前 R_i 在 R_j 前面。若使用某一排序算法排序后，R_i 仍然在 R_j 前面，则称此排序算法是**稳定的**；否则称其为**不稳定的**。

**排序的分类：**

* **内部排序**：排序期间元素全部存放在内存中的排序
* **外部排序**：排序期间元素无法全部同时放在内存中，必须在内外存之间移动数据的排序

### 7.1.2 排序算法的评价指标

1）**时间复杂度**：主要分析比较次数和移动次数2）**空间复杂度**：排序算法所需的辅助存储空间3）**稳定性**：是否能保证相等关键字的相对顺序不变

## 7.2 插入排序

### 7.2.1 直接插入排序

**算法思想**：每次将一个待排序的记录按其关键字大小插入到前面已经排好序的子序列中的适当位置，直到全部记录插入完成为止。
    void InsertSort(ElemType A[], int n) {
        int i, j;
        for (i = 2; i <= n; i++) {
            if (A[i] < A[i - 1]) {        // 若A[i]不小于其前驱，则无需插入
                A[0] = A[i];            // 复制为哨兵
                for (j = i - 1; A[0] < A[j]; --j)
                    A[j + 1] = A[j];    // 后移
                A[j + 1] = A[0];        // 插入到正确位置
            }
        }
    }

**性能分析：**

* **时间复杂度**：最好 O(n)（有序），最坏 O(n²)（逆序），平均 O(n²)
* **空间复杂度**：O(1)
* **稳定性**：稳定排序

### 7.2.2 折半插入排序

**算法思想**：在直接插入排序的基础上，使用折半查找来确定插入位置。

**性能分析：**

* **时间复杂度**：比较次数为 O(n log₂n)，移动次数仍为 O(n²)
* **空间复杂度**：O(1)
* **稳定性**：稳定排序

### 7.2.3 希尔排序（缩小增量排序）

**算法思想**：先将整个待排序的记录序列分割为若干子序列，分别进行直接插入排序，待整个序列中的记录"基本有序"时，再对全体记录进行一次直接插入排序。

具体做法：取一个小于 n 的整数 d₁ 作为第一个增量，把全部记录分成 d₁ 个组，所有距离为 d₁ 的倍数的记录放在同一个组中，在各组内进行直接插入排序；然后取第二个增量 d₂ < d₁，重复上述分组和排序工作，直至增量 d_t = 1（dt < d_{t-1} < ... < d₂ < d₁），即所有记录放在同一组中进行直接插入排序为止。

**性能分析：**

* **时间复杂度**：取决于增量序列的选择，约为 O(n^1.3) ~ O(n²)
* **空间复杂度**：O(1)
* **稳定性**：不稳定排序

## 7.3 交换排序

### 7.3.1 冒泡排序

**算法思想**：从后往前（或从前往后）两两比较相邻元素的值，若为逆序（即 A[i−1] > A[i]），则交换它们，直到序列比较完。这样一趟冒泡可将最大的元素放到最终位置（或最小的元素放到最前面）。
    void BubbleSort(ElemType A[], int n) {
        for (int i = 0; i < n - 1; i++) {
            bool flag = false;           // 表示本趟冒泡是否发生交换的标志
            for (int j = n - 1; j > i; j--)  // 一趟冒泡
                if (A[j - 1] > A[j]) {
                    swap(A[j - 1], A[j]);  // 交换
                    flag = true;
                }
            if (flag == false)
                return;                   // 本趟遍历后没有发生交换，说明表已经有序
        }
    }

**性能分析：**

* **时间复杂度**：最好 O(n)（有序），最坏 O(n²)（逆序），平均 O(n²)
* **空间复杂度**：O(1)
* **稳定性**：稳定排序

### 7.3.2 快速排序

**算法思想**：基于**分治**的策略。在待排序表 L[1...n] 中任取一个元素 pivot 作为基准，通过一趟排序将待排序表划分为独立的两部分 L[1...k−1] 和 L[k+1...n]，使得 L[1...k−1] 中的所有元素 ≤ pivot，L[k+1...n] 中的所有元素 ≥ pivot，则 pivot 放在了其最终位置 L[k] 上。这个过程称为一趟**快速排序**（或一次划分）。然后分别递归地对两个子表重复上述过程，直至每部分内只有一个元素或空为止。
    void QuickSort(ElemType A[], int low, int high) {
        if (low < high) {
            int pivotpos = Partition(A, low, high);  // 划分
            QuickSort(A, low, pivotpos - 1);         // 递归排序左子表
            QuickSort(A, pivotpos + 1, high);        // 递归排序右子表
        }
    }
    int Partition(ElemType A[], int low, int high) {
        ElemType pivot = A[low];        // 将当前表中第一个元素设为枢轴值
        while (low < high) {
            while (low < high && A[high] >= pivot) --high;
            A[low] = A[high];          // 比枢轴小的元素移到左边
            while (low < high && A[low] <= pivot) ++low;
            A[high] = A[low];          // 比枢轴大的元素移到右边
        }
        A[low] = pivot;                // 枢轴元素存放到最终位置
        return low;                    // 返回枢轴所在位置
    }

**性能分析：**

* **时间复杂度**：最好 O(n log₂n)（均衡划分），最坏 O(n²)（每次划分极不均衡），平均 O(n log₂n)
* **空间复杂度**：O(log₂n)（递归栈深度），最坏 O(n)
* **稳定性**：不稳定排序

**优化方法**：随机选取枢轴、三数取中法、当子表长度较小时改用直接插入排序等。

## 7.4 选择排序

### 7.4.1 简单选择排序

**算法思想**：每一趟在待排序元素中选择关键字最小（或最大）的元素，加到已排好序的子序列的最后（或最前），直到全部元素排序完毕。
    void SelectSort(ElemType A[], int n) {
        for (int i = 0; i < n - 1; i++) {
            int min = i;
            for (int j = i + 1; j < n; j++)
                if (A[j] < A[min])
                    min = j;            // 更新最小元素位置
            if (min != i)
                swap(A[i], A[min]);    // 与第i个位置交换
        }
    }

**性能分析：**

* **时间复杂度**：始终 O(n²)（无论有序与否都要进行比较）
* **空间复杂度**：O(1)
* **稳定性**：不稳定排序

### 7.4.2 堆排序

**堆**：堆是一棵完全二叉树，且满足以下任一条件：

* **大顶堆**：根结点的值 ≥ 所有子结点的值
* **小顶堆**：根结点的值 ≤ 所有子结点的值

**堆排序算法**：
    // 建立大顶堆
    void BuildMaxHeap(ElemType A[], int len) {
        for (int i = len / 2; i > 0; i--)
            AdjustDown(A, i, len);
        // 由数组下标高处往低处，从第一个可能需要调整的非叶结点
        // 开始检查，直到根结点（注意根结点下标不是0，是从1开始存储）
    }
    // 向下调整堆
    void AdjustDown(ElemType A[], int k, int len) {
        // A 是存储堆的数组，k 是需要检查的结点下标，len 是堆中结点个数
        A[0] = A[k];  // A[0] 暂存这个需要检查的结点值
        for (i = 2 * k; i <= len; i *= 2) {
            // 从这个结点的左孩子开始往下比较，
            // 如果发生交换，对交换过的结点继续和它的孩子比较
            if (i < len && A[i] < A[i + 1])
                i++;  // 如果右孩子大一些，就只要考虑和右孩子比较
            if (A[0] >= A[i])
                break;  // 如果这个结点的值不小于它的较大孩子结点值，则不需要交换
            else {
                A[k] = A[i];  // 如果这个结点的值小于它的较大孩子结点值，则将较大的孩子结点值赋值给该结点
                k = i;        // i 赋值给 k，也就是从 i 开始继续往下检查，直到所有结点检查结束
            }
        }
        A[k] = A[0];  // 检查到最后 k 的值就是最后一轮交换过的结点位置下标，将该结点换过去
    }
    // 堆排序
    void HeapSort(ElemType A[], int len) {
        BuildMaxHeap(A, len);          // 初始建堆
        for (i = len; i > 1; i--) {
            // n-1 趟的交换和建堆过程
            Swap(A[i], A[1]);         // 输出堆顶元素（和堆底元素交换）
            printf(A[i]);             // 输出堆顶元素
            AdjustDown(A, 1, i - 1);  // 把剩余的 i-1 个元素整理成堆
        }
    }

**堆排序的性能分析：**

**空间复杂度**：堆排序只需要在交换结点的时候需要额外存储空间来辅佐，所以空间复杂度为 O(1)。

**时间复杂度**：堆排序的总时间可以分为①建堆部分 + ② n − 1 次向下调整堆。

**①建堆部分**：时间复杂度为 O(n)。

假如有 N 个结点，那么高度为 H = ⌈log₂(n + 1)⌉，叶子结点的每个父结点最多只需要下调 1 次，倒数第二层的父结点最多只需要下调 2 次，根结点最多需要下调 H 次，而叶子结点的父结点共有 2^(H−1) 个，倒数第二层共有 2^(H−2) 个，根结点只有 1 个，所以最多需要调整次数为：

$$s = 1 \times 2^{H-1} + 2 \times 2^{H-2} + \ldots + (H-1) \times 2^1 + H \times 2^0 = 2N - 2 - \lceil\log_2(n+1)\rceil$$

**②调堆部分**：一次调堆从上至下最坏情况走得路径是从根结点到叶子结点，完全二叉树的高度为 ⌈log₂(n + 1)⌉，所以时间复杂度为 O(log₂n)。那么 n − 1 个顶点时间复杂度为 O(n log₂n)。

**堆排序的总时间复杂度**：O(n) + O(n log₂n) = O(n log₂n)

**稳定性**：堆排序**不稳定**。例如初始序列为 1 2 2'，由于 2 在左孩子位置，第一次交换之后 2' 换到了堆顶，所以 2' 最终排好的位置在最后，也就是 1 2' 2，两个 2 的位置发生了变化。

## 7.5 归并排序

### 7.5.1 归并排序的原理

假定待排序表含有 n 个记录，则可以看成是 n 个有序的子表，每个子表长度为 1，然后两两归并，得到 ⌈n/2⌉ 个长度为 2 或 1 的有序表；再两两归并，……如此重复，直到合并成一个长度为 n 的有序表为止，这种排序方法称为**2-路归并排序**。

**示例**：49 38 65 97 76 13 27① 首先将整个序列的每个关键字看成一个单独的有序的子序列② 两两归并，49 和 38 归并成 {38 49}，65 和 97 归并成 {65 97}，76 和 13 归并成 {13 76}，27 没有归并对象③ 两两归并，{38 49} 和 {65 97} 归并成 {38 49 65 97}，{13 76} 和 27 归并成 {13 27 76}④ 两两归并，{38 49 65 97} 和 {13 27 76} 归并成 {13 27 38 49 65 76 97}

### 7.5.2 归并排序的实现

    ElemType *B = (ElemType *)malloc((n + 1) * sizeof(ElemType));  // 辅助数组B（动态分配内存）
    
    // 归并——将表A的两段 A[low…mid] 和 A[mid+1…high] 各自有序，将它们合并成一个有序表
    void Merge(ElemType A[], int low, int mid, int high) {
        for (int k = low; k <= high; k++)
            B[k] = A[k];              // 将A中所有元素复制到B中
        for (int i = low, j = mid + 1, k = i; i <= mid && j <= high; k++) {
            // k 是归并之后数组的下标计数器
            if (B[i] <= B[j])        // 比较B的左右两段中的元素
                A[k] = B[i++];       // 将较小值复制到A中
            else
                A[k] = B[j++];
        }
        while (i <= mid)
            A[k++] = B[i++];        // 若第一个表未检测完，直接将剩下的部分复制过来
        while (j <= high)
            A[k++] = B[j++];        // 若第二个表未检测完，直接将剩下的部分复制过来
    }
    
    // 归并排序
    void MergeSort(ElemType A[], int low, int high) {
        if (low < high) {
            int mid = (low + high) / 2;      // 从中间划分两个子序列
            MergeSort(A, low, mid);          // 对左侧子序列进行递归排序
            MergeSort(A, mid + 1, high);     // 对右侧子序列进行递归排序
            Merge(A, low, mid, high);        // 归并
        }
    }

### 7.5.3 归并排序的性能分析

**时间复杂度**：

一共 n 个元素。第 ① 趟 Merge：子序列长度为 2，所以有 n/2 对子序列，每个子序列需要执行 1 次 Merge。Merge 时间复杂度为子序列长度之和即 2，所以第 ① 趟 merge 的时间复杂度为 O(n/2 × 2) = O(n)。

第 ② 趟 Merge：子序列长度为 4，所以有 n/4 对子序列，每个子序列需要执行 1 次 Merge，Merge 时间复杂度为子序列长度之和即 4，所以第 ② 趟 merge 的时间复杂度为 O(n/4 × 4) = O(n)。

……

第 k 趟归并：子序列长度为 2^k，所以有 n/2^k 对子序列。当 n/2^k = 1 时，k = log₂n，此时需要归并的两个子序列长度为 n/2，只需要一次 Merge 就能实现整个序列有序。所以一共执行了 k = log₂n 趟排序，每趟排序的时间复杂度都是 O(n)。

**所以整个归并排序的时间复杂度为 O(n log₂n)**。

**空间复杂度**：因为需要将这个待排序序列转存到一个数组，所以需要额外开辟大小为 n 的存储空间，即空间复杂度为 O(n)。

**稳定性**：归并排序是**稳定**的排序算法。因为在归并过程中，相等的元素总是保持原有的先后顺序。

## 7.6 基数排序

### 7.6.1 基数排序的原理

基数排序（也叫桶排序）是一种很特别的排序方法，它**不是基于比较**进行排序的，而是采用**多关键字排序思想**（即基于关键字各位的大小进行排序的），借助"分配"和"收集"两种操作对单逻辑关键字进行排序。基数排序又分为**最高位优先（MSD）排序**和**最低位优先（LSD）排序**。

**示例**：53, 3, 542, 748, 14, 214, 154, 63, 616

桶实际是一个队列，先进先出（从桶的上面进，下面出）。

补充位数：053, 003, 542, 748, 014, 214, 154, 063, 616

**第一次"分配"**（队列从上入队）：按个位数分配到桶 0 ~ 桶 9

**第一次"收集"**（队列从下出队）：054, 005, 006, 001, 021, 015, 061, 074, 154

**第二次"分配"**（队列从上入队）：按十位数分配

**第二次"收集"**（队列从下出队）：003, 014, 214, 616, 542, 748, 053, 154, 063

**第三次"分配"**（队列从上入队）：按百位数分配

**第三次"收集"**（队列从下出队）：003, 014, 053, 063, 154, 214, 542, 616, 748

由于关键字现在三个数位都排列有序，所以整个关键字序列都排列有序。

### 7.6.2 基数排序的性能分析

**空间复杂度**：需要开辟关键字基的个数个队列，所以空间复杂度为 O(r)。

关键字数量为 n，关键字的位数为 d（比如 748，d = 3），r 为关键字的基的个数，就是组成关键字的数据的种类，比如十进制数字一共有 0 至 9 一共 10 个数字，即 r = 10。

**时间复杂度**：需要进行关键字位数 d 次"分配"和"收集"，一次"分配"需要将 n 个关键字放进各个队列中，一次"收集"需要将 r 个桶都收集一遍。所以一次"分配"和一次"收集"时间复杂度为 O(n + r)。d 次就需要 O(d(n + r)) 的时间复杂度。

**稳定性**：由于是队列，先进先出的性质，所以在分配的时候是按照先后顺序分配，也就是稳定的，所以收集的时候也是保持稳定的。即**基数排序是稳定的排序算法**。

### 7.6.3 MSD 基数排序

MSD（最高位优先）基数排序：对桶中关键字个数不为 1 的桶递归排序。

过程：1）首先按最高位分配到桶 0 ~ 桶 92）对桶中关键字个数不为 1 的桶递归排序（对次高位进行分配）3）此时各个桶中都只有一个关键字，递归结束，收集各桶返回到上一层4）收集各桶：得到有序序列

## 7.7 外部排序

### 7.7.1 外部排序的基本概念

截止目前学习过的所有排序算法，都是建立在计算机的内存上进行。由于内存的大小限制，前面所学的排序算法都是针对数据量不是特别大的情况。所以这些排序都属于**内部排序**。

但是很多时候，需要对**大文件**进行排序，因为文件中的记录很多、信息量庞大，无法将整个文件拷贝进内存中进行排序。

**解决办法**：需要将待排序的记录存储在外存上，排序时再把数据一部分一部分的调入内存进行排序。在排序过程中需要多次进行内存和外存之间的交换，对外存文件中的记录进行排序后的结果仍然被放到原有文件中。这种排序的方法就叫做**外部排序**。

### 7.7.2 多路归并排序

**多路归并算法**：通过多路归并，就实现了在较小的内存容量完成大规模的数据排序。

一开始的这些有序的归并段如何得到？当然可以以单个数据为有序，然后一个一个数据调入内存中进行排序得到一些归并段。但是带来的开销会非常大。

### 7.7.3 置换-选择排序

**置换-选择排序**：用于从无序序列中得到初始的归并段。

**示例**：初始序列：17，21，05，44，10，12，56，32，29；内存大小：3

通过置换-选择排序，可以对无序的序列得到初始的归并段。不同的归并策略会导致归并次数不同，意味着需要进行的 I/O 操作次数不同。因此需要找到一种归并次数最少的归并策略来减少 I/O 操作次数。最佳归并策略由**最佳归并树**来解决。

### 7.7.4 最佳归并树

设由置换-选择得到 9 个初始归并段，其长度（记录数）依次为：9, 30, 12, 18, 3, 17, 2, 6, 24。现作 3-路平衡归并。

如果把各个归并段的长度记做是某个结点的权值，那么最佳归并树就是一棵 N 路的**哈夫曼树**。

**I/O 次数** = 2 × (2×3 + 3×3 + 6×3 + 9×2 + 12×2 + 30×1 + 17×2 + 18×2 + 24×2) = 446

### 7.7.5 败者树

最佳的归并策略可以通过最佳归并树来找到，但是对于多路归并来说，每次归并如何得到最值的关键字？

如果仍然采用内部排序中的归并排序算法，当归并的路数很大时，带来的额外开销将会比增大归并路数减少的开销要多，得不偿失。所以 m 路归并不能采用内部排序算法来进行。

**败者树**可以看成是一棵完全二叉树：

* 这棵树的**叶子结点**存储的是各个归并段当前参加比较的记录
* **内部结点**存储的则是左右子树当中的**失败者**
* **胜利者**则一直继续向上比较直到根结点

由于每次归并我们都是希望找到各个归并段中最小的关键字，所以胜利者应该是左右子树中关键字较小的。

**败者树的顶端就是最后的胜者，即当前归并记录中关键字最小的值。**

**稀疏矩阵的存储方式：**1）**三元组表**：按行优先（或列优先）顺序存储所有非零元素的三元组2）**十字链表**：既有行指针又有列指针的链式存储结构

## 附录B 森林

### B.1 森林的定义

森林是 m（m ≥ 0）棵互不相交的树的集合。每棵树去掉根结点后，其各棵子树又构成了森林。

### B.2 森林的遍历

**先序遍历森林**：若森林非空，则访问森林中第一棵树的根结点，先序遍历第一棵树根结点的子树森林，先序遍历除去第一棵树之后剩余的树构成的森林。

**中序遍历森林**：若森林非空，则中序遍历森林中第一棵树的根结点的子树森林，访问第一棵树的根结点，中序遍历除去第一棵树之后剩余的树构成的森林。

### B.3 森林与二叉树的转换

森林转换为二叉树的方法已在第四章 4.3.2 节详述。本质上是"左孩子右兄弟"规则的推广。

## 1. 二叉排序树 / 二叉搜索树 (BST: Binary Search Tree / Binary Sort Tree)

_注：二叉排序树和二叉搜索树通常指代同一种数据结构。_

**详细概念：**

二叉搜索树是一种对节点值有严格顺序要求的二叉树。它可以是空树，或者满足以下性质的二叉树：

* 若它的左子树不为空，则**左子树上所有节点的值均小于它的根节点的值**。

* 若它的右子树不为空，则**右子树上所有节点的值均大于它的根节点的值**。

* 它的左、右子树也分别为二叉搜索树。

**重要性质：**

* **中序遍历**一棵二叉搜索树，可以得到一个**严格递增的有序序列**。

* 没有键值相等的节点（在标准定义中，若有重复值通常放在一边或用计数器处理）。

**优点：**

* 将查找、插入、删除操作的平均时间复杂度从线性表（数组、链表）的 $O(n)$ 降低到了 $O(\log n)$。

* 结构简单，易于实现。

**缺点：**

* 在最坏情况下（例如按顺序插入元素 `1, 2, 3, 4, 5`），树会退化成一个单链表，此时查找的时间复杂度会退化为 $O(n)$。

**C++ 节点表示：**

C++
    template <typename T>
    struct BSTNode {
        T val;
        BSTNode* left;
        BSTNode* right;
        BSTNode(T x) : val(x), left(nullptr), right(nullptr) {}
    };

## 2. 平衡二叉树 (AVL Tree)

**详细概念：**

为了解决 BST 可能退化成链表的问题，苏联数学家 G.M. Adelson-Velsky 和 E.M. Landis 发明了 AVL 树。它是一种**高度平衡**的二叉搜索树。

**重要性质：**

* 它首先是一棵二叉搜索树。

* 对于树中的任意一个节点，它的**左子树和右子树的高度差（平衡因子）的绝对值不能超过 1**。

* 平衡因子 (Balance Factor) = 左子树高度 - 右子树高度。它的值只能是 -1、0 或 1。

**优点：**

* 严格控制了树的高度，保证了在最坏情况下，查找、插入、删除的时间复杂度都稳定在 $O(\log n)$。

**缺点：**

* **维护平衡的代价高昂**：为了保持严格的平衡，在插入和删除节点时，经常需要进行树的旋转（左旋、右旋、双旋），这在频繁写入的场景下会导致性能下降。

## 3. 红黑树 (Red-Black Tree)

**详细概念：**

红黑树是一种**弱平衡**（或称近似平衡）的二叉搜索树。它通过给节点涂上红色或黑色，并遵循特定的颜色规则，来确保没有一条路径会比其他路径长出两倍。

**重要性质（必须同时满足的 5 条规则）：**

1. 每个节点或者是红色，或者是黑色。

2. **根节点是黑色**。

3. 每个叶子节点（这里的叶子指为空的 NIL 节点）是黑色。

4. 如果一个节点是红色的，则它的**两个子节点都是黑色的**（即不能有两个连续的红色节点）。

5. 从任一节点到其每个叶子的所有简单路径都包含**相同数目的黑色节点**。

**优点：**

* 相比于 AVL 树，红黑树降低了对平衡的严格要求（左右子树高度差最多2倍），从而**减少了插入和删除时的旋转次数**。

* 查找、插入、删除的综合性能极佳，时间复杂度均为 $O(\log n)$。（插入删除性能显著优于AVL，但查找操作较多时，AVL树仍然为首选（树高最小））

* 在工业界应用极广（C++ STL 中的 `std::map`、`std::set`，Java 的 `TreeMap`，Linux 内核的完全公平调度器 CFS 等均采用红黑树）。

**C++ 节点表示：**

C++
    enum Color { RED, BLACK };
    template <typename T>
    struct RBTreeNode {
        T val;
        Color color;
        RBTreeNode* left;
        RBTreeNode* right;
        RBTreeNode* parent; // 红黑树通常需要父节点指针来回溯变色和旋转
        RBTreeNode(T x) : val(x), color(RED), left(nullptr), right(nullptr), parent(nullptr) {}
        // 新插入的节点默认是红色的，这样最容易满足规则5，随后再调整
    };

### 结论

（1）  从根到叶结点的最长路径不大于最短路径（全为黑结点）的2倍

（2）n个内部结点红黑树的高度 <= log2(n+1). （由根的黑高不小于 h/2得来）。

（3）新插入的结点应为红色（不破坏其他性质，只在破坏“不红红”性质时才进行调整。

1）插入流程：

（1）以二叉查找树规则插入z，将其涂为红色，若父节点为黑色，插入结束。

## 4. 线索二叉树 (Threaded Binary Tree)

**详细概念：**

在含有 $n$ 个节点的二叉链表中，有 $n+1$ 个空指针域。线索二叉树就是利用这些**空闲的指针域来存放指向该节点在某种遍历序列下的前驱或后继节点的指针**。这些附加的指针就被称为“线索”。

**重要性质：**

* 需要增加标志位（通常为 `ltag` 和 `rtag`）来区分指针指向的是真正的子节点，还是遍历的前驱/后继线索。
  
  * `ltag == 0`：`left` 指向左孩子； `ltag == 1`：`left` 指向前驱。
  
  * `rtag == 0`：`right` 指向右孩子；`rtag == 1`：`right` 指向后继。

**优点：**

* **空间利用率高**：充分利用了原本浪费的空指针域。

* **遍历速度快**：一旦建立了线索，就可以像遍历双向链表一样以 $O(n)$ 的时间复杂度和 $O(1)$ 的空间复杂度遍历整棵树，**无需递归也无需借助栈**。

**C++ 节点表示：**

C++
    template <typename T>
    struct ThreadNode {
        T val;
        ThreadNode* left;
        ThreadNode* right;
        bool ltag; // 左线索标志：false为孩子，true为前驱
        bool rtag; // 右线索标志：false为孩子，true为后继
        ThreadNode(T x) : val(x), left(nullptr), right(nullptr), ltag(false), rtag(false) {}
    };

### 5. 遍历序列中的规律与特点

对于二叉树的先序、中序、后序遍历，有以下绝对规律：

| **遍历方式**              | **访问顺序**    | **序列特点与规律**                                                                                 |
| --------------------- | ----------- | ------------------------------------------------------------------------------------------- |
| **先序遍历 (Pre-order)**  | 根 -> 左 -> 右 | **序列的第一个元素永远是树（或子树）的根节点**。                                                                  |
| **中序遍历 (In-order)**   | 左 -> 根 -> 右 | 1. **在 BST、AVL、红黑树中，中序遍历必定是一个有序递增序列**。<br>2. 给定一个根节点的值，在中序序列中，它左边的元素全属于它的左子树，右边的元素全属于它的右子树。 |
| **后序遍历 (Post-order)** | 左 -> 右 -> 根 | **序列的最后一个元素永远是树（或子树）的根节点**。常用于需要先处理左右子树最后处理当前节点的场景（如删除整棵树、计算树的高度）。                          |

### 1. 路径与路径长度（基本定义）

* **路径**：从树中一个结点到另一个结点所经过的分支序列。

* **路径长度**：路径上经过的**边的条数**（也即分支数量）。

例如：从根结点 R 到叶子结点 L 经过 3 条边，则这条路径的长度为 3。

### 2. 结点的深度与高度（与根路径长度的关系）

* **结点的深度**：从**根结点到该结点**的路径长度（边数）。  
  根结点的深度为 0。

* **结点的高度**：从**该结点到其最远叶子**的路径长度（边数）。

### 3. 树的路径长度（Path Length, PL）

* **定义**：树中**所有结点深度之和**（即所有结点到根结点的路径长度总和）。

* 记作：  
  `PL = Σ depth(结点i)`

对于一棵二叉树，PL 越小，说明结点整体越靠近根部，查找效率通常越高。

### 4. 内部路径长度与外部路径长度（二叉树扩展）

将普通二叉树扩展为**满二叉树**（给所有空位置补上“外部结点”），有两种路径长度：

* **内部路径长度（IPL）**：所有**内部结点**（原树结点）的深度之和。

* **外部路径长度（EPL）**：所有**外部结点**（空叶子的占位符）的深度之和。

**定理**（针对二叉树）：  
`EPL = IPL + 2n`  
其中 n 是内部结点的个数。

该概念常用于分析二叉查找树的平均查找长度。

### 5. 带权路径长度（WPL）与哈夫曼树

* **结点的权**：给每个叶子结点赋予一个代表频率或重要性的数值。

* **结点的带权路径长度**：从根到该叶子的**路径长度 × 叶子的权值**。

* **树的带权路径长度（WPL）**：所有叶子结点的带权路径长度之和。

`WPL = Σ (w_i × l_i)`

其中 w_i 是第 i 个叶子的权，l_i 是根到该叶子的路径长度。

**应用**：哈夫曼树（最优二叉树）就是在给定叶子权值下，使 WPL 最小的二叉树，广泛用于数据压缩和最优决策。

### 6. 最长路径（树的直径）

* **树的直径**：树中任意两结点之间的**最长简单路径长度**（按边数或按结点数定义需统一）。  
  它是衡量树“宽窄”的一个全局特征，常用于网络路由和树的中心性分析。
  
  

## B树与B+树

<u>**总结**</u>

（1）**<u>相同点</u>**：都能高效支持随机查找

这是它们作为**平衡多路搜索树**的共同优势。

* **查找逻辑一致**：从根节点开始，利用节点内部有序的键值进行二分定位，确定下一层子节点指针，逐层向下直到叶子。

* **复杂度相同**：IO次数与树高成正比，均为 O(logm​N)。数据项都在同一层（B树数据在任意层，B+树只在叶子层），查单个记录的代价稳定且低。
  
  

（2）**<u>只有B+树能高效支持顺序查找</u>**

**B树为什么不行（需中序遍历，随机IO）**  
B树的数据记录分散在**非叶子节点**和**叶子节点**。想遍历所有数据（如 `SELECT * FROM table ORDER BY id`），必须做**中序遍历**。这会导致指针在树的不同层级、不同物理页之间频繁来回跳转，磁盘表现为**大量随机IO**，性能很差。

**B+树为什么可以（叶子链表，顺序IO）**  
B+树有两个关键设计：

1. **数据仅存叶子**：保证遍历只访问最底层节点。

2. **叶子节点双向链表**：相邻叶子节点由指针串连。

**效果**：只需一次随机查找定位起点，之后顺着链表指针依次读取叶子页即可。磁盘表现为**顺序IO**，读取速度接近磁盘极限带宽，这正是数据库索引普遍选用B+树的主因。

### B树

#### 一、 B树的定义与核心特点

B树是一种**平衡的多路搜索树**，主要用于磁盘或其他直接存取的辅助存储设备，它被设计用来极大程度地减少磁盘I/O操作次数。

对于一棵 $m$ 阶（$m \ge 2$）的B树，其必须满足以下**事实与规则**：

1. **根节点约束**：如果根节点不是叶子节点，那么它至少有 $2$ 个子节点。

2. **节点度数（子节点数）约束**：除根节点和叶子节点外，每个内部节点至少有 $\lceil m/2 \rceil$ 个子节点，至多有 $m$ 个子节点。

3. **关键字约束**：每个节点包含 $n$ 个关键字，所有的关键字按升序排列。其中子节点的数量恰好比关键字的数量多 $1$（即 $n$ 个关键字划分出 $n+1$ 个区间）。因此，一个节点内的关键字数量范围是 $\lceil m/2 \rceil - 1 \le n \le m - 1$。

4. **搜索树性质**：节点中的关键字 $K_i$ 将子树的数据分割开，即第 $i$ 个子树中所有节点的关键字都处在 $K_{i-1}$ 和 $K_i$ 之间。

5. **绝对平衡**：**所有的叶子节点都必须位于同一层**（即树的高度是绝对平衡的）。

* * *

#### 二、 B树的高度 ($h$) 分析

高度分析是B树的核心价值所在。我们可以分析在包含 $N$ 个总关键字的情况下，B树的高度 $h$ 的界限。

**分析推导**：

如果B树包含了 $N$ 个关键字，那么必定有 $N+1$ 个叶子节点（叶子节点即为查找失败的外部节点）。 （即 $n$ 个关键字划分出 $n+1$ 个区间，查找失败的结点就分布在这些区间中）

根据我们在第二部分的推导，第 $h+1$ 层（即叶子节点所在的逻辑层）的节点数至少为 $2 \times (\lceil m/2 \rceil)^{h-1}$。

#### 三、 核心操作原理（查找、插入、删除）

##### 1. 查找 (Search)

* **过程**：从根节点开始，将目标值与节点内的关键字（有序数组）进行比较（通常使用二分查找）。如果命中则返回；如果目标值小于某个关键字，则顺着对应的指针进入下一层子树，直到找到或到达叶子节点。

* **时间复杂度**：磁盘I/O次数为 $O(h)$，内存中比较次数为 $O(h \log m)$。

##### 2. 插入 (Insert)

* **过程**：插入操作**始终发生在最底层的叶子节点**。

* **分裂机制（重点）**：如果插入后该节点的关键字数量达到了 $m$（违背了 $m-1$ 的上限），则必须进行**节点分裂（Split）**。
  
  * 将该节点从中间位置（第 $\lceil m/2 \rceil$ 个关键字）一分为二。
  
  * 将中间的关键字“向上提取”到父节点中。
  
  * 如果父节点也满了，则继续向上分裂，最极端的情况下会导致根节点分裂，此时**B树的高度增加 1**。

##### 3. 删除 (Delete)

删除操作相对复杂，需要保证删除后节点关键字数不低于 $\lceil m/2 \rceil - 1$。

* **情况A（删除叶子节点元素）**：直接删除。如果导致关键字不足，则向相邻的兄弟节点“借”关键字（通过父节点旋转）。如果兄弟节点也不够借，则将该节点、兄弟节点以及父节点中的分隔关键字进行**合并（Merge）**。

* **情况B（删除内部节点元素）**：不能直接删除。找到该关键字的**前驱**（左子树最大值）或**后继**（右子树最小值）来替代它，然后转为在叶子节点中删除那个前驱或后继。

| ---------- | --------------------------------- | ----------------------------- | ---------------------------------------------------------- |
| **数据存储位置** | 所有节点（内部节点和叶子节点）都存储数据内容（或数据记录的指针）。 | **只有叶子节点**存储真实数据，内部节点仅作为索引使用。 | **B+树内部节点可以容纳更多索引**，相同数据量下树高更低，I/O更少。                      |
| **叶子节点结构** | 叶子节点之间独立，无连接。                     | 叶子节点之间通过**双向链表**相连。           | **B+树极大地优化了范围查询（Range Query）**，只需找到起点即可顺着链表遍历，而B树需要进行中序遍历。 |
| **查询稳定性**  | 最好情况可能在根节点直接命中（$O(1)$ 级I/O）。      | 必须查找到叶子节点才能命中。                | B+树的查询时间复杂度绝对稳定于 $O(h)$，而B树会有波动。                           |

### B+树



 **“节点的关键字数等于其子树个数（$k$ 个关键字对应 $k$ 个子树）”** 这一标准，通常被称为<u>数据库/系统流派（</u>例如著名的经典教材《数据库系统概念》以及 MySQL InnoDB 存储引擎的底层逻辑均倾向于这种设计）。



###### 这种设计的逻辑本质

与“作为分割线（$k-1$ 个关键字）”不同，在这种设计中，内部节点的关键字**不再是悬空的分割线，而是其对应子树中关键字的最大值（或最小值）的严格副本**。

* **结构对齐**：`children[i]` 这个子树里的所有值，其最大值（或最小值）一定等于 `keys[i]`。关键字与子树指针在数组索引上是一一对应的（长度完全相等）。

* **工程优势**：这种对齐极大地简化了代码逻辑（不需要处理 $N$ 个指针对应 $N-1$ 个关键字的边界偏移），并且在更新或删除叶子节点的最大值时，只需顺藤摸瓜向上更新对应的父节点关键字即可，逻辑更加清晰。

#### 一、 $m$ 阶 B+ 树的严格条件与定义

B+ 树是 B 树的一种变体，被广泛应用于数据库和操作系统的文件系统中。一棵 $m$ 阶的 B+ 树需要满足以下核心条件（事实标准）：

1. **节点分支数约束**：每个内部（非叶子）节点最多拥有 $m$ 个子树（即最多 $m$ 个指针）。

2. **节点下限约束**：除根节点外，每个内部节点至少有 $\lceil m/2 \rceil$ 个子树。根节点如果不是叶子节点，至少有 $2$ 个子树。

3. **关键字与指针的数量关系**：
   
   * **分析式说明**：关于这一点，学术界有细微的流派差异。在最普遍的标准中，如果一个内部节点有 $k$ 个子树，那么它包含 k个关键字。
   
   * 所有的关键字都在叶子节点中出现（内部节点中的关键字是其对应子树中关键字的最大值（或最小值）的严格副本）。

4. **数据分离（核心隔离特性）**：**所有的卫星数据（真实数据记录或其物理地址指针）全部存储在叶子节点中**。内部节点（非叶子节点）**仅存储路由关键字（索引）**，不附带任何真实数据。

5. **叶子节点链表化**：所有的叶子节点都位于同一层，并且**叶子节点之间通过指针链接**（通常是双向链表），形成一个按关键字从小到大排序的顺序链表。

#### 二、 B+ 树与 B 树的多维差异分析（全景对比）

我们可以通过以下表格，清晰地量化并对比两者在结构、性能和应用场景上的差异：

| **对比维度**    | **B 树 (B-Tree)**            | **B+ 树 (B+ Tree)**        | **差异带来的工程优势推演**                                                                                      |
| ----------- | --------------------------- | ------------------------- | ---------------------------------------------------------------------------------------------------- |
| **数据存储位置**  | 所有节点（内部、叶子）均可携带数据。          | **仅叶子节点**携带数据，内部节点纯做路由。   | **推测与分析**：由于磁盘页（如 16KB）大小固定，B+ 树内部节点不存数据，就能塞入成百上千个索引关键字。这意味着 **B+ 树更加“矮胖”，树高 $h$ 更低，磁盘 I/O 次数显著减少**。 |
| **叶子节点连通性** | 叶子节点彼此孤立，无指针相连。             | 叶子节点通过**双向链表**串联。         | B+ 树极大地优化了**范围查询（Range Query）**和全表扫描。无需像 B 树那样进行复杂的中序遍历回溯，只需找到起点顺着链表读即可。                             |
| **查询时间复杂度** | 最好 $O(1)$（根节点命中），最坏 $O(h)$。 | **绝对稳定在 $O(h)$**。         | B+ 树任何查询都必须走到叶子节点，虽然牺牲了最好情况，但带来了企业级应用最看重的**查询时间稳定性**。                                                |
| **关键字重复性**  | 树中每个关键字全局唯一。                | 内部节点的关键字在叶子节点中必然存在（作为副本）。 | B+ 树内部节点即使被删除关键字，只要路由逻辑正确，甚至可以延缓物理删除，维护成本更低。                                                         |

#### 三、 核心操作的区别与联系（查找、插入、删除）

B+ 树的优点在于：

    **IO次数更少**：由于B+树在内部节点上不包含数据信息，因此在内存页中能够存放更多的key。 数据存放的更加紧密，具有更好的*<u>***空间局部性***</u>*。因此访问叶子节点上关联的数据也具有**<u>更好的缓存命中率</u>**。
    遍历更加方便**：B+树的叶子结点都是相链的，因此对整棵树的遍历只需要一次线性遍历叶子结点即可。而且由于数据顺序排列并且相连，所以便于区间查找和搜索。而B树则需要进行每一层的递归遍历。相邻的元素可能在内存中不相邻，所以<u>**缓存命中性**</u>没有B+树好。

B+ 树的增删查改逻辑脱胎于 B 树，但在具体执行时，由于“数据隔离”和“链表结构”，产生了一些关键区别。

##### 1. 查找 (Search)

* **联系**：两者在内部节点中的查找逻辑完全一致，都是从根往下走，通过二分或顺序比对关键字确定子树分支。

* **区别**：
  
  * **单点查询**：B 树如果在内部节点找到匹配的关键字，就**直接返回数据并结束**；B+ 树即使在内部节点匹配到了关键字，也**必须继续向下走到叶子节点**才能拿到数据。
  
  * **<u>范围查询（例如找 10 到 50 之间的数）</u>**：B 树需要执行繁琐的树中序遍历，不断在父子节点间反复跳跃；B+ 树只需查找到 10 所在的叶子节点，然后顺着底层链表一直遍历到 50 即可，效率呈指数级碾压。

##### 2. 插入 (Insert) 与 节点分裂 (Split)

* **联系**：都是先查找到底层的叶子节点进行插入；如果节点关键字达到满载（上限），都会触发分裂（Split）操作，并将中间关键字向上提取。

* **区别（关键点）**：
  
  * **B 树的分裂**：中间关键字被提取到父节点后，原节点**不再保留**该关键字。
  
  * **B+ 树叶子节点的分裂**：中间关键字被提取到父节点作为路由索引时，**该关键字依然会保留在分裂后的新叶子节点中**（通常作为右半部分叶子的第一个元素），因为叶子必须保证数据的完整性。
  
  * _(注：B+ 树内部节点的分裂逻辑则与 B 树一模一样，不再保留副本。)_

##### 3. 删除 (Delete)

* **联系**：都会涉及借用（Borrow，兄弟旋转）和合并（Merge），以维持节点下限 $\lceil m/2 \rceil - 1$。

* **区别（B+ 树的删除逻辑更简单）**：
  
  * 在 B 树中，如果删除的是**内部节点**的关键字，极其复杂，必须去子树中寻找前驱或后继来做物理替换。
  
  * 在 B+ 树中，**删除操作永远且仅发生在叶子节点**（因为只有叶子有数据）。如果被删除的关键字恰好也是内部节点的路由索引，**根据工程实现的不同，甚至可以不去管内部节点的那个副本**（因为它仍能充当大于某值、小于某值的分界线），或者在合并操作顺便替换。这种特性使得 B+ 树的并发控制（Latching）实现比 B 树容易得多。

#### 四、 工程应用与全景总结

基于上述分析，我们可以得出以下**事实结论**：

在纯内存算法题中，B 树的综合理论时间期望略微优于 B+ 树（因为 B 树可以提前在半路命中）。**但是，一旦将战场转移到“磁盘”和“数据库存储”中，B+ 树取得了决定性胜利。**

以 MySQL 的 **InnoDB 存储引擎** 为例：

操作系统读取磁盘是以“页（Page）”（通常是 4KB 或 16KB）为单位的。如果使用 B 树，页内混杂了臃肿的数据，一个 16KB 的页可能只能存几十个节点，导致树高轻易突破 5 层。

而使用 B+ 树，内部节点的 16KB 纯粹用来存 64位（8字节）的整型主键和指针，一个节点可以轻松拥有超过 1000 个分支（$m > 1000$）。

**推演：** 树的高度 $h = \log_{1000}(N)$。即使表中有两千万条数据（$N = 20,000,000$），树的高度也仅仅是 **3 层**。这意味着，在千万级数据中精准查找一条记录，最多只需 3 次磁盘 I/O（如果根节点常驻内存，则只需 2 次）。加上其底层链表对 `SELECT * FROM table WHERE id > 100 AND id < 500` 这种范围查询的无缝支持，造就了 B+ 树作为现代关系型数据库索引基石的地位。

## B*树

__B_ 树（B-star tree）_* 为了解决 B+ 树在某些极端场景下的空间浪费和频繁分裂问题，而演化出的核心“延迟分裂”与“满载均衡”机制。

B树是B+树一种变形，它是在B+树的基础上，**将索引层以指针连接起来，使搜索取值更加快捷。**

![2a304a1970ec7f49db496f45d21e9cb3](https://i-blog.csdnimg.cn/blog_migrate/2a304a1970ec7f49db496f45d21e9cb3.png)

但是B树又在B+树的基础上产生了一系列的变化，如下：

（1）B*树定义了非叶子结点关键字个数至少为(2/3)*M，即块的最低使用率为2/3，代替B+树的1/2；
（2）B+树的分裂：当一个结点满时，分配一个新的结点，并将原结点中1/2的数据复制到新结点，最后在父结点中增加新结点的指针；B+树的分裂只影响原结点和父结点，而不会影响兄弟结点，所以它不需要指向兄弟的指针；
（3）B*树的分裂：当一个结点满时，如果它的下一个兄弟结点未满，那么将一部分数据移到兄弟结点中，再在原结点插入关键字，最后修改父结点中兄弟结点的关键字（因为兄弟结点的关键字范围改变了）；如果兄弟也满了，则在原结点与兄弟结点之间增加新结点，并各复制1/3的数据到新结点，最后在父结点增加新结点的指针；
所以B树相对于B+树，空间利用率上有所提高，查询速率也有所提高。

#### 一、 B* 树的核心优势总结

B* 树的设计哲学可以概括为：**“能匀（借）则匀，绝不轻易分裂”**。这种机制带来了以下显著优势：

1. **极致的空间利用率**：
   
   * B+ 树在最坏情况下（例如完全逆序插入），节点可能始终徘徊在 $1/2$ 的满载率，导致一半的磁盘空间被浪费（即索引膨胀）。
   
   * B* 树通过强制要求节点最低使用率为 $2/3$，使得同样数量的数据，占用的磁盘物理页（Page）更少，缓存命中率（Buffer Pool Hit Rate）更高。

2. **更低的树高（更少的 I/O）**：
   
   * 因为每个节点能塞入更多的数据（平均密度从 50%~75% 提升到 66%~83%），在宏观数据量千万级别的场景下，B* 树的分支因子（Fanout）更大，树的高度 $h$ 被进一步压缩，直接减少了全表扫描和点查的磁盘 I/O 次数。

3. **极大地降低了结构变更（分裂）的频率**：
   
   * 节点分裂是一项非常昂贵的操作（涉及分配新内存/磁盘页、数据拷贝、修改父节点）。B* 树通过先向兄弟节点“转移”数据，将昂贵的“节点分裂”转化为廉价的“节点内数据移动”，大大平滑了大量数据插入时的性能抖动。

* * *

### 二、 B* 树与 B+ 树的量化差异对比

我们可以通过下表，清晰地看出两者在结构和动态维护策略上的差异：

| **对比维度**    | **B+ 树**          | **B* 树**                          | **差异带来的影响分析**                                                      |
| ----------- | ----------------- | --------------------------------- | ------------------------------------------------------------------ |
| **节点最低满载率** | $1/2$             | **$2/3$**                         | B* 树对空间的压榨更极致，但维持该下限的算法逻辑更复杂。                                      |
| **非叶子节点指针** | 仅指向子树（纵向）         | 指向子树（纵向） + **指向兄弟节点（横向）**         | B* 树的非叶子节点也串联成了链表，方便在溢出时快速探查兄弟节点的剩余容量。                             |
| **溢出处理策略**  | 立即一分为二（**1 变 2**） | 先尝试匀给兄弟；都不行则两个满节点分裂为三个（**2 变 3**） | B* 树的“2变3”策略保证了分裂出的新节点每个都有 $2/3$ 的满载率，避免了 B+ 树刚分裂完节点只有 $1/2$ 满的尴尬。 |
| **写放大效应**   | 较大（频繁分裂引发链式向上更新）  | **较小**（绝大多数插入被兄弟吸收）               | 纯顺序插入场景下 B+ 树有优化，但在随机插入场景下，B* 树的吞吐量更平稳。                            |

* * *

### 三、 分析式表达：为什么 B* 树没有像 B+ 树那样“一统天下”？

既然 B* 树在空间和理论查询效率上都优于 B+ 树，为什么我们在 MySQL (InnoDB)、PostgreSQL 等主流关系型数据库中，最常听到的依然是 B+ 树呢？

这就涉及到**理论与工程落地的折衷（Trade-off）**。在工业级并发数据库中，B* 树面临着致命的**并发控制（Latching/Locking）噩梦**：

* **B+ 树的并发锁模型相对简单**：插入数据时，通常只需要锁住当前节点和父节点。

* __B_ 树的锁冲突范围被指数级放大_*：当一个节点满了需要向兄弟“匀”数据时，线程必须同时获取**当前节点的写锁、兄弟节点的写锁、以及父节点的写锁**（因为要修改父节点的路由关键字）。如果两个线程同时从左右向中间节点“匀”数据，极易引发**死锁（Deadlock）**。

* **推论与事实**：因此，在多核高并发时代，主流数据库宁愿牺牲一点磁盘空间（磁盘现在很便宜），采用 B+ 树配合“惰性分裂/合并”策略，来换取多线程并发写入时极高的吞吐量，而不愿为了提升空间利用率去承担 B* 树复杂的锁竞争代价。
  
  

### 一、 为什么 MySQL 选择 B+ 树做索引？（存储引擎视角）

MySQL 的索引主要依赖于底层的存储引擎实现。

#### 1. 存储引擎与索引类型的匹配（⚠️ 纠错与补充）

* **(a) InnoDB 存储引擎**：默认且最核心的是 **B+Tree 索引**。
  
  * _补充_：InnoDB 的 B+Tree 是一种**聚簇索引（Clustered Index）**，即主键 B+ 树的叶子节点直接包含了完整的数据行。

* **(b) MyISAM 存储引擎**：默认也是 **B+Tree 索引**。
  
  * _纠错_：您提到 MyISAM 默认是 Fulltext（全文索引），这其实是一个常见的认知偏差。MyISAM 确实是早期 MySQL 中**唯一支持**全文索引的引擎（直到 5.6 版本 InnoDB 才支持），但它的**常规默认索引依然是 B+Tree**。
  
  * _补充_：与 InnoDB 不同，MyISAM 的 B+Tree 是**非聚簇索引**，叶子节点不存真实数据，只存指向数据物理地址的指针。

* **(c) Memory 存储引擎**：默认是 **Hash 索引**。
  
  * _补充_：Memory 表数据存在内存中，Hash 索引查找单条记录极快（$O(1)$）。但因为哈希散列的无序性，它**不仅不支持范围查找和排序，也不支持最左前缀匹配（如 `LIKE 'abc%'`）**，如果遇到哈希冲突，还会退化为链表遍历。

#### 2. B+ 树的工程级优化（基于您的总结做深度延展）

* **带有双向顺序访问指针的 B+ 树**：
  您提到叶子节点增加了指向相邻节点的指针。
  
  * _工程补充_：在 MySQL InnoDB 的实际实现中，叶子节点之间构成的是**双向链表**。这种设计不仅极大地提高了像 `id BETWEEN 18 AND 49` 这样的正向区间查询效率，还能完美支持 `ORDER BY ... DESC` 的**逆序范围扫描**。

* **磁盘 I/O 的极限榨取（预读原理）**：
  您提到将一个节点的大小设为等于一个页。
  
  * _数据补充_：在 InnoDB 中，这个“页（Page）”的默认大小是 **16KB**。数据库利用了操作系统的**局部性原理与磁盘预读**，每次 I/O 刚好读取一个 16KB 的节点进内存。因为内部节点只有索引没有数据，这 16KB 可以塞下上千个关键字，使得拥有千万级数据的 B+ 树高度通常只有 3 层（只需 3 次 I/O）。

* * *

### 二、 B+ 树相较于 B 树的四大绝对优势（提炼您的观点）

基于数据库的查询诉求，B+ 树的四大优势可以严密推导如下：

1. **磁盘读写代价更低（“矮胖”结构）**：B+ 树的内部节点去掉了具体数据（卫星数据），使得一个物理盘块（Page）能容纳更多的索引关键字。单次 I/O 读入内存的关键字呈指数级增加，极大地降低了总体的磁盘 I/O 次数。

2. **查询效率绝对稳定**：由于非终结节点只是路由索引，真正的数据全部在叶子节点。所有查询目标的命中路径长度完全相同（都等于树高 $h$），不会出现 B 树那种“运气好在根节点查到，运气差在叶子节点查到”的性能波动。

3. **极度契合全表扫描与遍历**：B 树分支节点也存数据，要扫全库必须进行极耗性能的**中序遍历**（在各层级节点间反复横跳引发随机 I/O）。而 B+ 树只需找到最左侧的叶子节点，顺着底层链表“一扫到底”即可，非常适合数据库的备份和全量统计。

4. **完美解决范围查询（Range Query）**：数据库业务中 `>、<、BETWEEN` 操作极为频繁。B+ 树结合底层链表，只需一次查找到边界点，即可实现 $O(1)$ 级别步长的连续读取，彻底解决了 B 树遍历效率低下的痛点。

### 三、 总结：多路搜索树的演进史 (The Evolution Path)

根据您的精炼总结，我们可以将这条数据结构的演化之路以**对比图鉴**的形式定格：

| **数据结构**           | **核心约束与形态**                                        | **痛点与局限**                         | **演进意义**                                      |
| ------------------ | -------------------------------------------------- | --------------------------------- | --------------------------------------------- |
| **二叉搜索树 (BST)**    | 每个节点存 1 个关键字；左小右大。                                 | 极易退化为链表；在磁盘系统中树高太高，I/O 次数爆炸。      | 奠定了搜索树比较查找的基础逻辑。                              |
| **B 树 (B-Tree)**   | 多路搜索树；节点存 $m/2$ 到 $m$ 个关键字；**所有节点均可存储数据，命中即返回**。   | 范围查询必须中序遍历，效率极低；节点体积大导致树不够扁平。     | 引入了**“度”和“分裂”**机制，打破二叉限制，第一次专为磁盘 I/O 设计。      |
| **B+ 树 (B+ Tree)** | B 树变体；非叶子节点纯做索引；**所有数据全在叶子节点，且叶子节点增加双向链表**。        | 极端顺序插入时，空间利用率可能跌至 50%（$1/2$）。     | 彻底解决了**范围查询**和**树高限制**，成为现代关系型数据库的绝对基石。       |
| __B_ 树 (B_ Tree)** | B+ 树升级版；**非叶子节点也增加链表**；最低空间利用率强制从 $1/2$ 提升到 $2/3$。 | 节点满载时优先向兄弟节点借位，**极易引发高并发场景下的死锁**。 | 将**空间利用率**和**延缓分裂**推向极致，但因并发控制成本过高，未能取代 B+ 树。 |
