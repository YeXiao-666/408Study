    head->next = NULL;
    while (p != NULL) {
        q = p->next;
        p->next = head->next;
        head->next = p;
        p = q;
    }
}

B. 将链表原地逆置（头插法重建）

6.数据结构 具有 $n$ 个结点的完全二叉树（Complete Binary Tree）的高度（层数）为 $\lceil\log_2(n+1)\rceil$。 对于一棵具有 $n$ 个结点的满二叉树（Full Binary Tree），其叶结点数为 ______， 度为 $2$ 的结点数为 ______。
A. $\frac{n+1}{2}$；$\frac{n-1}{2}$
B. $\frac{n}{2}+1$；$\frac{n}{2}-1$
C. $\frac{n}{2}$；$\frac{n}{2}-1$
D. $n-1$；$1$
【答案与解析】
A。性质推导：对于任意非空二叉树，若叶子数为 $n_0$，度为 $2$ 的结点数为 $n_2$，则恒有 $n_0 = n_2 + 1$（重要性质！）。 满二叉树所有分支结点度均为 $2$，故 $n = n_0 + n_2 = n_0 + n_0 - 1 = 2n_0 - 1$，解得 $n_0 = \frac{n+1}{2}$，$n_2 = \frac{n-1}{2}$。
🔗 跨学科联动：此性质在哈夫曼树（Huffman Tree）构建中用于验证编码总长度最优性，同时与操作系统进程调度中的多叉树结构有内在联系。

8.数据结构 用 Kruskal 算法构造带权无向连通图的最小生成树（MST）， 若图中有 $n$ 个顶点和 $e$ 条边，则该算法的时间复杂度为 ______； 若使用并查集（Union-Find）优化，则主要耗时在于 ______。
A. $O(e\log e)$；对边按权值排序
B. $O(n^2)$；寻找最小权值的跨割边

D. $O(n^2)$；判断是否形成环

算法策略时间复杂度适用场景

9.数据结构 对关键字序列 $\{49, 38, 65, 97, 76, 13, 27, \underline{49}\}$ 进行一趟快速排序（以第一个元素 $49$ 为枢轴）， 则一趟划分后的结果为 ______。（注：下划线表示第二个 $49$）
A. $\{27, 38, 13, 49, 76, 97, 65, \underline{49}\}$
B. $\{27, 38, 13, \underline{49}, 49, 76, 97, 65\}$
C. $\{13, 27, 38, 49, 76, 97, 65, \underline{49}\}$
D. $\{\underline{49}, 38, 13, 27, 49, 76, 97, 65\}$
【答案与解析】
A。Hoare 划分过程（双向扫描法）： 设 $pivot = arr[0] = 49$，$low=0$，$high=7$：
  1. $high$ 从右向左找 $< pivot$ 的元素：$arr[7]=\underline{49}$ 不小于，$arr[6]=27 < 49$ → 停在 $high=6$
  2. $arr[low] = arr[high]$ → $arr[0]=27$
  3. $low$ 从左向右找 $\ge pivot$ 的元素：$arr[1]=38 < 49$，$arr[2]=65 \ge 49$ → 停在 $low=2$
  4. $arr[high] = arr[low]$ → $arr[6]=65$
  5. $high$ 继续左移：$arr[5]=13 < 49$ → 停在 $high=5$
  6. $arr[low] = arr[high]$ → $arr[2]=13$
  7. $low$ 右移：$arr[3]=97 \ge 49$ → 停在 $low=3$
  8. $arr[high] = arr[low]$ → $arr[5]=97$
  9. $high$ 左移至 $low=3$，退出循环，$arr[low] = pivot = 49$
结果：$\{27, 38, 13, \mathbf{49}, 76, 97, 65, \underline{49}\}$。注意两个相等枢轴的处理是易错点！
10.数据结构 对 $n$ 个元素进行堆排序（Heap Sort），建初始堆的时间复杂度为 ______， 每次调整堆（Heapify）的时间复杂度为 ______，整个堆排序的总时间复杂度为 ______。
A. $O(n)$；$O(\log n)$；$O(n\log n)$
B. $O(n\log n)$；$O(\log n)$；$O(n\log n)$
C. $O(n)$；$O(n)$；$O(n^2)$
D. $O(n\log n)$；$O(n)$；$O(n^2)$
【答案与解析】
A。关键结论：
  • 建堆（Build Heap）：从最后一个非叶结点 $\lfloor n/2 \rfloor$ 向上调用 SiftDown，总时间为 $O(n)$（不是 $O(n\log n)$！这是一个高频考点）
  • 单次堆调整（SiftDown）：树高为 $h$ 时最多比较/交换 $h$ 次，即 $O(\log n)$
  • 整体堆排序：建堆 $O(n)$ + $(n-1)$ 次删除堆顶并调整 $O((n-1)\log n)$ = $O(n\log n)$
🔗 工程应用场景：堆排序常用于实现优先队列（Priority Queue），在操作系统进程调度（如 Linux CFS 完全公平调度器）和 Dijkstra 最短路径算法中均有直接应用。
11.数据结构 对长度为 $n$ 的有序顺序表进行折半查找（Binary Search）， 其判定树（Decision Tree）是一棵 ______，查找成功时的最大比较次数为 ______， 平均查找长度（ASL）约为 ______。
A. 平衡二叉树；$\lfloor\log_2 n\rfloor+1$；$O(\log n)$
B. 完全二叉树；$\lceil\log_2(n+1)\rceil$；$O(n)$
C. 二叉排序树；$n$；$O(\log n)$
D. 满二叉树；$n-1$；$O(1)$
【答案与解析】
A。折半查找判定树性质：
  • 判定树形状：接近平衡二叉搜索树（AVL），但不一定是完全二叉树
  • 树高 $h = \lfloor\log_2 n\rfloor + 1$（查找成功的最大比较次数）
  • 查找失败的外部结点在第 $h$ 层或 $h+1$ 层
  • $ASL_{成功} = \frac{1}{n}\sum_{i=1}^{n}(l_i)$，其中 $l_i$ 为第 $i$ 个元素所在层数，量级为 $O(\log n)$
  • $ASL_{失败} \approx O(\log n)$
与顺序查找（$ASL = (n+1)/2 = O(n)$）形成鲜明对比，体现了预排序换取对数查找效率的经典权衡思想。

15.计组 某 Cache 采用直接映射（Direct Mapped）方式，主存容量为 $512KB$，Cache 容量为 $4KB$， 块大小为 $64B$。则主存地址中Tag 字段的位数为 ______， 行号（Line Index） 字段位数为 ______，块内地址（Block Offset） 位数为 ______。

41. 数据结构 [10分] 已知带头结点的单链表 $L$，结点结构为 $\{data, next\}$，设计一个时间复杂度为 $O(n)$、 空间复杂度为 $O(1)$ 的算法，将链表中所有值为 $x$ 的结点删除。 要求：
(1) 给出算法的基本设计思想；（3分）
(2) 使用 C 或 C++ 语言描述算法，关键之处给出注释；（5分）
(3) 说明算法的时间复杂度和空间复杂度。（2分）
【参考答案与评分标准】
(1) 算法思想（3分）：

使用双指针法（前驱-当前指针同步推进）从头到尾扫描链表。维护指针 $pre$ 指向当前考察结点的前驱，$p$ 指向当前结点。若 $p->data == x$，则通过修改 $pre->next$ 跳过 $p$ 结点并释放之；否则 $pre$ 和 $p$ 同步后移。由于链表的单向性，删除操作必须借助前驱指针，因此双指针是必然选择。

(2) 算法实现（5分）： 
void DeleteAllX(LinkList& L, ElemType x) {
    // pre 指向当前结点的前驱，初始指向头结点
    Node* pre = L;
    // p 从首元结点开始扫描
    Node* p = L->next;
    
    while (p != NULL) {
        if (p->data == x) {
            // 找到待删结点：pre 不动，p 后移，释放中间结点
            Node* q = p;
            p = p->next;
            pre->next = p;   // 跳过 q
            free(q);         // 释放内存，防止泄漏
        } else {
            // 未找到：双指针同步后移
            pre = p;
            p = p->next;
        }
    }
}
(3) 复杂度分析（2分）：
  • 时间复杂度：$O(n)$ —— 只需一次遍历，每个结点最多被访问一次
  • 空间复杂度：$O(1)$ —— 仅使用了常数个辅助指针变量（$pre$, $p$, $q$）
🔗 跨学科联动：此题的"原地删除"思想与操作系统内存管理中的紧凑（Compaction）算法有相通之处——都是在有限的空间约束下通过指针/地址重定向来实现元素的批量移除。此外，链表操作的指针维护能力也是实现进程控制块（PCB）链表管理的基础技能。
42. 数据结构 [13分] 设一棵二叉树以二叉链表为存储结构，结点结构为 $\{lchild, data, rchild\}$。 设计算法完成以下任务：

【参考答案与评分标准】
(1) 非递归中序遍历（5分）： 
void InOrderTraversal(BiTree T) {
    InitStack(S);           // 初始化辅助栈
    BiTNode* p = T;         // p 为工作指针
    
    while (p != NULL || !IsEmpty(S)) {
        if (p != NULL) {
            // ① 一直向左走到底，沿途结点入栈
            Push(S, p);
            p = p->lchild;
        } else {
            // ② 左子树为空：弹出栈顶（回溯到最近的祖先）
            Pop(S, p);
            visit(p->data);  // ★ 访问结点（中序位置）
            
            // ③ 转向右子树
            p = p->rchild;
        }
    }
}

核心逻辑：沿左分支入栈保存路径 → 栈顶弹出并访问 → 转右子树。栈的作用是记录回溯路径——当左子树遍历完毕后，通过弹栈返回父结点访问之，再进入右子树。这与递归调用中系统栈保存的活动记录（Activation Record）功能完全等价。

(2) 求二叉树宽度（8分）： 
int GetWidth(BiTree T) {
    if (T == NULL) return 0;
    
    LinkQueue Q;             // 层序遍历用的队列
    InitQueue(Q);
    EnQueue(Q, T);
    
    int maxWidth = 0;        // 记录最大宽度
    
    while (!isEmpty(Q)) {
        int levelSize = QueueLength(Q);  // 当前层的结点数
        maxWidth = max(maxWidth, levelSize);  // 更新最大宽度
        
        // 处理当前层的所有结点
        for (int i = 0; i < levelSize; i++) {
            BiTNode* node;
            DeQueue(Q, node);
            
            if (node->lchild != NULL)
                EnQueue(Q, node->lchild);
            if (node->rchild != NULL)
                EnQueue(Q, node->rchild);
        }
    }
    return maxWidth;
}

算法思想：利用层序遍历（BFS），每轮处理一层。关键技巧是用 levelSize = QueueLength(Q) 在每层开始时记录当前队列长度（即该层结点数），然后恰好弹出这么多结点并将其子女入队。这样自然实现了"逐层隔离"。时间复杂度 $O(n)$，空间复杂度 $O(w)$（$w$ 为最大宽度）。

🔗 跨学科联动：二叉树的层序遍历与计算机网络中的BFS 最短路径算法（如 RIP 距离向量路由）共享相同的"逐层扩展"思想。同时，二叉树宽度概念在操作系统多级反馈队列调度（MLFQ）中也有类比——每一级队列可以看作一个"层"，调度器关注各队列长度以决定优先级动态调整策略。

(1) 信号量定义（3分）：

void Worker() {                    // 工人进程（生产者）
    while (true) {
        生产一个产品 item;
        
        P(empty);                   // ① 申请一个空位（若无空位则阻塞）
        P(mutex);                   // ② 进入临界区

        in = (in + 1) % N;          // 环形入队

(3) 包装工进程 Consumer（3分）： 
void Packer() {                    // 包装工进程（消费者）
    while (true) {
        P(full);                    // ① 申请一个产品（若无产品则阻塞）
        P(mutex);                   // ② 进入临界区
        
        从 buffer[out] 取出 item;
        out = (out + 1) % N;        // 环形出队
        
        V(mutex);                   // ③ 退出临界区
        V(empty);                   // ④ 空位数+1，唤醒可能的工人
        
        打包 item;
    }
}

关键注意事项（高频扣分点）：

  1. P 操作顺序不能颠倒：必须先 P(empty/full)，再 P(mutex)。若先 P(mutex 再 P(empty)，可能导致持有锁后等待条件而死锁（因为其他进程无法进入临界区来改变条件）
  2. V 操作顺序：先 V(mutex) 再 V(full/empty），减少临界区长度
  3. 环形缓冲区的 in/out 指针更新必须在临界区内完成，保证互斥
  4. 此解法支持多生产者-多消费者（$M$ 个工人 + $K$ 个包装工），mutex 保证任意时刻只有一个进程操作缓冲区

(2) Belady 异常（3分）：

是的，FIFO 存在 Belady 异常。经典例子：页面引用串为 $1, 2, 3, 4, 1, 2, 5, 1, 2, 3, 4, 5$

  • $3$ 个页框时：FIFO 缺页 $9$ 次（如上计算）
  • $4$ 个页框时：FIFO 缺页可能为 $10$ 次（增加页框反而缺页更多！）

原因分析：FIFO 仅根据"进入内存的时间"决定淘汰对象，忽略了页面的实际访问模式。当增加一个页框后，改变了后续页面的驻留组合，可能导致原本命中的页面被过早淘汰出去，之后又需要重新调入。这种现象被称为 Belady 异常（Belady's Anomaly），1969 年由 Belady 发现。

工程启示：实际系统中更倾向于使用 LRU（或其近似算法如 Clock/NRU），因为 LRU 属于 Stack 算法，保证了"更多内存绝不会更差"的直觉正确性。

(1) 主机 A 能否一次性发送这 $2048$ 字节的数据？如果不能，本次实际能发送多少字节？（2分）

(1) 发送能力判断（2分）：
$$\text{当前有效发送窗口} = \min(rwnd, cwnd) - \text{已发送未确认}$$ $$= \min(4000, 3000) - 1500 = 3000 - 1500 = 1500 \text{ 字节}$$

(2) IP 分片分析（3分）：

(3) 拥塞窗口变化（2分）：

当前处于慢启动阶段（cwnd < ssthresh），每收到一个 ACK，cwnd 增加 $1$ MSS：

$$\text{收到 ACK 前：} cwnd = 2920 = 2 \times MSS$$ $$\text{收到 1 个 ACK（确认 1460 字节 = 1 MSS）后：}$$ $$cwnd = 2920 + 1460 = 4380 = 3 \times MSS$$

若 $4380 \ge ssthresh$，则下一个 RTT 后进入拥塞避免阶段（cwnd 开始线性增长）。 新的有效发送窗口 = $\min(5000, 4380) - (\text{新的已发送未确认})$。
